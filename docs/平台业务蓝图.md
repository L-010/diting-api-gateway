# API Gateway 开发者平台业务蓝图

## 1. 文档用途与适用范围

本文说明当前平台实际提供的业务能力、参与角色、使用流程与边界，是《管理员操作指南》和《用户操作指南》的共同依据。

平台的目标是把部署在不同服务器上的专业工具，统一接入为对外可调用的 API 服务。管理员负责接入、审核和发布工具接口；用户只通过统一的 API Gateway 调用已上线接口，不接触工具的真实部署地址和机器凭证。

本文只描述当前系统已经具备或有明确启用条件的功能。未实现的多租户、自动故障转移、自动值班告警等能力不会被当作现有功能说明。

## 2. 平台如何运转

```text
独立工具服务
  -> 管理员登记工具与服务连接信息
  -> 管理员导入并治理工具接口
  -> 平台发布统一 Gateway 路由
  -> 用户取得平台 API Key
  -> 用户程序调用 Gateway
  -> Gateway 鉴权、限流、权限校验并转发
  -> 返回工具结果，并记录调用记录
```

### 2.1 三方职责

| 参与方 | 主要工作 | 不负责的工作 |
| --- | --- | --- |
| 工具服务提供方或技术同事 | 部署工具服务，提供服务地址、认证信息、健康检查地址与 OpenAPI/Swagger 文档 | 不直接向最终用户公开服务器地址或上游凭证 |
| 平台管理员 | 审批用户，接入工具，审核接口，设置访问策略，发布路由，查看调用和审计 | 不需要在平台中重新开发工具本身 |
| 平台用户 | 申请账号，创建 API Key，阅读接口文档，通过统一 Gateway 调用服务 | 不直接访问工具服务器，不管理其他用户或工具配置 |

### 2.2 对外与对内边界

对用户公开的是统一 Gateway 地址、工具名称、接口说明、请求参数、请求示例和标准错误信息。用户不应看到真实上游服务器地址、上游 Token、机器认证 Header、上游内部路径或实例拓扑。

平台 API Key 只用于用户程序向平台 Gateway 证明身份。它不等于平台向工具服务使用的 Bearer Token 或 Header API Key，也不会被原样透传到工具服务。

Gateway 只接受管理员已发布、工具处于启用状态且当前 Key 有权调用的接口。它不是通用 HTTP 代理，不能被用来转发任意 URL。

## 3. 角色、状态与权限

| 角色或状态 | 可以做什么 | 不能做什么 |
| --- | --- | --- |
| 公开访客 | 查看公开工具信息，注册、验证邮箱、登录 | 查看内部工具地址、调用用户接口、创建 Key |
| 待审批用户 | 完成注册和邮箱验证，等待管理员处理 | 登录使用门户或调用 Gateway |
| 已审批用户 | 使用门户、创建自己的 Key、查看可用工具和自己的调用、任务、文件 | 查看他人资源、工具上游配置、管理平台 |
| 临时密码用户 | 登录后修改密码 | 在改密前使用受保护门户与 Gateway |
| 停用或拒绝用户 | 查看受控提示并联系管理员 | 使用已有会话、Key 或 Gateway |
| 管理员 | 管理用户、Key、工具、接口策略、发布、监控、审计和平台设置 | 不能在页面中取回用户完整 Key 或上游 Token |

当前系统只有 `user` 和 `admin` 两类角色，没有组织、项目、租户或细粒度管理员角色。

## 4. 统一术语

| 名称 | 业务解释 | 系统中的含义 |
| --- | --- | --- |
| 平台 | 集中管理工具并统一对外提供 API 的系统 | API Gateway 开发者平台 |
| 工具 | 一个独立接入的平台服务，例如某项科研、计算或数据处理能力 | 一条工具配置，包含名称、slug、上游服务和接口集合 |
| 工具说明 | 面向管理员和用户的用途说明 | 工具详情与用户文档展示的描述 |
| 工具 slug | 工具的唯一短名称 | 小写字母、数字和短横线组成；创建后不可修改，也是 Gateway 路径的一部分 |
| 独立部署服务 | 由服务提供方单独运行的工具程序 | 工具的真实后端服务，可部署在不同服务器 |
| 上游服务 | Gateway 实际转发到的独立部署服务 | 由管理员配置的唯一服务端 |
| 上游根地址 | 平台访问工具服务的内部入口 | 仅管理员配置和脱敏查看；普通用户不可见 |
| Gateway | 平台统一的 API 调用入口 | `/gateway/{tool_slug}/{path}` |
| 统一网关地址 | 用户程序请求的域名与协议部分 | 由平台设置、环境配置或当前访问域名确定 |
| Gateway 前缀 | 某个工具在统一入口下的固定起始路径 | 通常为 `/gateway/{tool_slug}` |
| Gateway 路径 | 用户实际调用的接口路径 | Gateway 前缀加上管理员发布的接口路径 |
| 上游路径 | 工具服务器内部使用的接口路径 | 仅供平台转发使用，不对普通用户展示 |
| 接口或 Endpoint | 工具的一项具体能力，如查询、创建、下载 | 包含方法、路径、参数、请求体、响应和策略 |
| 路由 | 平台对外暴露某个接口的地址及执行规则 | 包含 Gateway 路径、限流、超时、访问策略等 |
| 已发布路由 | 已经过治理并允许 Gateway 调用的路由 | 工具启用时可对符合条件的用户开放 |
| OpenAPI/Swagger | 描述工具 API 的标准文档 | 用于导入接口定义，支持 URL、文件或文本来源 |
| 导入批次 | 一次导入或同步产生的一组接口结果 | 用于追踪本次导入、差异和确认状态 |
| 同步差异 | 新文档与现有接口之间的变化 | 例如新增、删除或修改接口，需要管理员判断 |
| 草稿 | 工具或接口尚未对用户开放的状态 | 可继续配置与治理，不能作为用户可调用服务 |
| 已启用 | 工具允许 Gateway 接收已发布接口请求 | 工具停用会使其 Gateway 请求返回受控失败 |
| 已停用 | 工具暂不接受 Gateway 请求 | 已发布接口不会继续供用户调用 |
| 放行 | 管理员同意某候选接口进入发布范围 | 仍需满足发布校验后才会对用户开放 |
| 排除 | 本次不把接口纳入平台对外服务 | 不等同于删除工具服务器上的接口 |
| 阻断 | 明确禁止接口在平台上线 | 常用于管理、内部调试、删除或风险不清晰接口 |
| 发布 | 把已确认接口生成可调用 Gateway 路由 | 不代表平台部署了工具服务器本身 |
| 访问策略 | 平台决定谁能调用接口和访问什么资源的规则 | `authenticated`、`owner`、`shared`、`admin_only` |
| 资源 | 用户调用产生或引用的数据对象 | 例如任务、数据集、文件、制品等 |
| 创建者资源 | 只允许创建者访问的资源 | `owner` 策略下按路径、查询或请求数据校验归属 |
| 任务 | 工具异步处理产生的工作项 | 需要工具配置任务适配能力才会出现在任务中心 |
| 文件与制品 | 任务输入、过程、结果、日志或归档文件 | 需要工具文件契约和文件 worker 支持 |
| 平台 API Key | 用户程序调用 Gateway 的凭证 | 以 `agw_` 开头，完整值只显示一次 |
| Key 前缀 | 用于识别某把 Key 的非敏感片段 | 可用于排障和管理，不能用于调用 |
| 上游 Token | 平台访问工具服务时使用的机器凭证 | 加密保存，只可替换，不会回显 |
| request_id | 单次请求的唯一排障编号 | 用户和管理员可据此定位同一次 Gateway 调用 |
| 调用记录 | Gateway 请求的脱敏审计记录 | 包含状态码、耗时、流量、错误码和 request_id |
| 监控指标 | 调用量、成功率、延迟、限流等汇总数据 | 面向管理员查询和排障 |
| 告警 | 对调用异常的聚合提示 | 当前以页面查询和统计为主，不是完整通知和值班闭环 |
| 用户级限流 | 一个用户在一分钟内可发起的总请求上限 | 由管理员设置默认值或按用户覆盖 |
| Key/工具级限流 | 某把 Key 调用某个工具的每分钟上限 | 由工具运行配置控制 |
| 邮件 worker | 异步投递验证、找回和邮箱变更邮件的进程 | SMTP 已配置时才具备完整邮件能力 |
| 文件 worker | 同步、校验和清理远程文件的进程 | 任务/文件能力启用时需要运行 |
| 健康检查 | 平台检查能否连接工具服务的动作 | 使用工具的健康检查路径，不等于完整业务验收 |
| 配置版本 | 一次工具运行配置保存的历史快照 | 用于识别并发修改和回溯变更 |
| 回滚 | 将工具运行配置恢复到历史版本 | 需由管理员在运行配置中操作 |

## 5. 接口访问策略

| 策略 | 适合的业务场景 | 用户能看到和做什么 |
| --- | --- | --- |
| `authenticated` | 不区分用户资源的普通服务，如公开算法计算 | 已审批且有效的用户可调用 |
| `owner` | 用户自己的任务、文件、数据集或结果 | 只能访问自己创建或被登记为自己所有的资源 |
| `shared` | 管理员明确确认可共享的全局数据 | 已审批用户可访问同一份共享数据，应谨慎使用 |
| `admin_only` | 平台管理、诊断或内部运维接口 | 普通用户文档不展示，只有管理员可用 |

`shared` 是接口级共享模式，不表示系统具备组织、项目或租户级共享能力。当前资源默认只归创建者所有。

## 6. 两条主业务流程

### 6.1 管理员：把工具变成可调用服务

1. 收集工具服务信息和接口文档。
2. 确认工具服务器属于平台允许连接的上游主机范围。
3. 新建工具，填写名称、slug、说明、上游地址、认证和健康检查。
4. 保存草稿并执行连接测试。
5. 导入 OpenAPI/Swagger，得到候选接口和风险提示。
6. 对每个接口选择放行、阻断或排除，并确认访问策略和资源规则。
7. 完成发布前校验，发布所有已放行接口。
8. 用低风险测试调用验证 Gateway、查看 request_id 和监控记录。
9. 后续通过同步差异、运行配置、监控和审计持续维护。

### 6.2 用户：从获准访问到稳定调用

1. 注册并完成邮箱验证。
2. 等待管理员审批；管理员导入的账号先修改临时密码。
3. 登录后查看门户概览和快速接入说明。
4. 创建 API Key，并立即把完整 Key 保存到用户自己的后端环境或密钥管理系统。
5. 在“工具与接口”中选择已上线工具，阅读接口说明与示例。
6. 使用统一 Gateway 地址、Gateway 路径和 `X-API-Key` 请求头调用接口。
7. 在调用记录中查询结果；失败时保存 request_id 并交给管理员排查。
8. 在 Key 临期、泄露或更换程序时按“先建新 Key、切换程序、再禁用旧 Key”轮换。

## 7. 当前能力边界

- 当前只有普通用户和管理员两类角色，没有组织、项目、租户或只读管理员角色。
- 每个工具当前只有一个生效上游地址，没有多实例优先级、自动故障转移或多环境切换。
- 新建 Key 默认可调用全部已发布且启用的工具接口；当前没有面向普通用户的工具级 Key 授权配置界面。
- SMTP 未配置时，公开注册验证、找回密码和邮箱变更会关闭；管理员创建、CSV 导入和临时密码流程仍可使用。
- 任务、文件和制品不是每个工具默认提供的能力，依赖任务适配、文件契约和文件 worker。
- 监控和告警当前用于查询、统计和排障，不代表已经具备自动通知、确认关闭或值班响应闭环。
- 在平台设置中填写 Gateway 公网地址不会自动配置 DNS、TLS、反向代理或服务器部署。
- 管理员界面仅展示脱敏后的上游信息；普通用户不展示真实上游信息。
- 生产环境仍需单独确认数据库、TLS、反向代理、进程托管、备份恢复、容量、日志采集和告警响应。

## 8. 面向两份操作指南的写作原则

- 管理员指南以“业务目的、准备什么、点击什么、如何判断成功、失败怎么办”为主，技术字段放在解释框或附录。
- 用户指南以“怎么获得权限、怎么调用、怎么保护 Key、怎么排障”为主，不要求理解内部部署与数据库。
- 两份指南都必须使用本文件定义的名称，并将“当前已实现”“有条件启用”“当前限制”明确区分。
- 文档、示例和截图不得包含真实上游地址、完整 Token、完整 API Key、真实用户隐私或生产敏感数据。
