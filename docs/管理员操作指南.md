# 管理员操作指南

## 1. 这份指南给谁看

本指南面向负责工具上线、用户审批和日常运营的业务管理员。管理员不需要开发工具服务，但需要和工具服务提供方或技术同事共同确认服务地址、接口文档和对外开放范围。

管理员的核心工作不是把服务器部署到平台中，而是把已经独立部署的工具服务安全地接入平台，审核哪些接口可以对用户开放，并通过统一 Gateway 发布和管理这些服务。

## 2. 上线一个工具前，请先准备这些信息

向工具服务提供方或技术同事收集下表信息。信息不完整时，不要先发布接口。

| 需要的信息 | 用途 | 应由谁提供 |
| --- | --- | --- |
| 工具名称和业务说明 | 用户在目录和接口文档中看到的内容 | 业务负责人或工具服务提供方 |
| 工具 slug | 统一 Gateway 路径的一部分，创建后不可修改 | 管理员与技术同事共同确认 |
| 上游根地址 | 平台连接真实工具服务的内部地址 | 工具服务提供方 |
| 健康检查路径 | 平台验证服务可达性 | 工具服务提供方 |
| 上游认证方式和凭证 | 平台访问工具服务时使用 | 工具服务提供方 |
| OpenAPI/Swagger 文档 | 平台识别接口、参数和响应 | 工具服务提供方 |
| 接口开放清单 | 判断哪些接口可对用户开放 | 业务负责人和工具服务提供方 |
| 资源归属规则 | 判断任务、文件、数据集等是否只属于创建者 | 业务负责人和工具服务提供方 |
| 任务、文件、制品能力说明 | 判断是否需要额外适配和 worker | 工具服务提供方 |

开始前还要确认：工具服务器已加入平台允许的上游主机范围。这个范围由部署平台的技术人员维护；若服务器不在范围内，连接测试与发布校验会失败。

## 3. 管理员日常入口

| 菜单 | 用途 | 何时使用 |
| --- | --- | --- |
| 管理总览 | 查看待审批用户、工具健康、阻断接口和近期问题 | 每日巡检或处理异常时 |
| 工具管理 | 新建工具、导入接口、治理、发布和维护运行配置 | 工具上线与变更时 |
| 用户管理 | 审批注册、导入用户、停用账号、设置用户限流 | 用户开通和权限处置时 |
| 平台设置 | 设置站点信息、邮件、默认用户限流和公开 Gateway 地址 | 首次配置或平台规则调整时 |
| 监控告警 | 查询调用量、失败、延迟、限流和 request_id | 用户报障或日常观察时 |
| 审计日志 | 查看管理员关键操作的留痕 | 复盘、审核或追溯变更时 |
| 任务与文件 | 查看工具产生的任务、文件、下载和同步状态 | 已启用相关能力的工具出现问题时 |

## 4. 标准流程：接入并发布一个新工具

### 第一步：新建工具草稿

进入“工具管理”，选择“新建工具向导”。向导按以下顺序引导配置：基本信息、部署环境、服务端认证、API 来源、导入预览、公共策略、校验测试、提交发布。

| 字段 | 如何理解 | 填写要点 |
| --- | --- | --- |
| 工具名称 | 管理员和用户看到的名称 | 使用业务名称，避免只写内部代号 |
| slug | 工具的永久短名称 | 仅使用小写字母、数字和短横线；确认后不可修改 |
| 工具说明 | 用户理解工具用途的主要内容 | 写明能做什么、适用对象和明显限制 |
| 上游根地址 | 平台实际转发的服务地址 | 只能由管理员填写；不能写入用户文档 |
| 健康检查路径 | 用于连通性检查的接口路径 | 通常由服务提供方提供，如 `/health` |
| 服务端认证 | 平台如何向工具服务认证 | 选择无认证、Bearer Token 或 Header API Key；凭证只输入或替换，不会回显 |
| API 来源 | 接口定义从哪里导入 | 可从上游默认地址、指定 URL、上传 JSON/YAML 或粘贴文本获取 |
| 工具级限流 | 单把 Key 调用该工具的每分钟上限 | 依据工具承载能力和业务优先级设置 |
| 超时和重试 | Gateway 等待上游服务的规则 | 慢任务不能仅靠增加超时解决，应优先采用任务型接口 |
| TLS 和网络隔离 | 平台到工具服务器的连接要求 | 由技术同事确认；不要因排错而随意降低安全设置 |

完成基本信息并保存后，工具仍是草稿。保存成功只表示配置已记录，不表示用户已经可以调用。

### 第二步：连接测试

在新建向导或工具工作台中执行“连接测试”或“健康检查”。

- 连接成功表示平台能够到达工具服务的健康检查接口。
- 连接失败时，优先核对上游地址、端口、健康检查路径、允许主机范围、网络访问规则和上游认证。
- 连接成功不代表所有业务接口都能正确使用，仍需导入、治理和发布。

不要把连接测试结果当作用户可用性的最终证明。

### 第三步：导入 OpenAPI/Swagger

选择工具的 API 来源并执行导入。平台会读取接口文档，生成候选接口和导入批次。

导入后的状态说明：

| 结果 | 含义 | 下一步 |
| --- | --- | --- |
| 候选接口 | 已从文档识别，但还没有对用户开放 | 逐项审核用途、风险和访问策略 |
| 待判断 | 差异或接口尚未完成业务决定 | 明确放行、阻断、排除或延后 |
| 阻断 | 平台认为风险较高或不适合直接上线 | 确认是否长期禁止或补充规则后处理 |
| 排除 | 本次不纳入平台对外服务 | 保留在上游服务中，但 Gateway 不提供 |
| 已发布 | 已生成 Gateway 路由 | 仍需结合工具启用状态和 Key 权限才能调用 |

导入不会自动发布接口。管理、内部调试、删除、全局列表和资源归属不清晰的接口需要特别谨慎。

### 第四步：治理接口并选择访问策略

进入工具工作台的接口目录或单接口详情，对每项候选接口回答以下问题：

1. 这个接口是否需要对普通用户开放？
2. 它是否属于内部管理、调试、删除、修复或高风险操作？
3. 它是否操作用户自己的任务、文件、数据集或结果？
4. 它是否返回所有用户都可以看到的公共数据？
5. 用户侧看到的名称、说明、参数和示例是否清楚且不含内部信息？
6. 请求大小、响应大小、超时、重试和 Content-Type 是否符合工具能力？

访问策略按业务含义选择：

| 选择 | 适用情况 | 管理员应确认的事项 |
| --- | --- | --- |
| 平台用户可调用 `authenticated` | 不涉及个人资源的普通服务 | 所有审批用户是否都可使用 |
| 仅资源创建者 `owner` | 任务、文件、数据集或结果等个人资源 | 资源 ID 从哪里获取，如何确认归属 |
| 平台用户共享 `shared` | 确认可公开共享的全局数据 | 是否真的允许所有用户看到相同数据 |
| 仅管理员 `admin_only` | 运维、管理、内部诊断能力 | 普通用户不应在文档中看到该接口 |

对于 `owner` 接口，资源规则必须完整。规则无法安全判断归属时，平台会拒绝调用而不会把未过滤的数据返回给用户。

### 第五步：发布前检查与发布

在点击发布前逐项确认：

- 所有候选接口都已经有明确处理结果：放行、阻断或排除。
- 没有未处理的高风险差异或待判断项目。
- Gateway 路径没有冲突。
- 需要资源归属的接口已经配置完整规则。
- 工具健康检查可达，认证和上游地址正确。
- 对用户开放的名称和说明没有泄露服务器、Token 或内部路径。

平台会在发布时做校验。发布成功后，已放行接口才会成为可调用的 Gateway 路由；发布失败时，应根据页面提示补齐未决策项、策略或配置问题后再试。

### 第六步：发布后验证

发布后请完成一次最小验证：

1. 用普通用户身份进入“工具与接口”，确认该工具和已发布接口已出现。
2. 使用测试账号的一把有效 Key 调用一个低风险接口。
3. 在“调用记录”或“监控告警”中按 request_id 找到本次调用。
4. 验证用户侧没有看到真实上游地址、上游 Token 或机器认证 Header。
5. 对一个受控失败场景确认返回的是标准错误，而不是内部服务器信息。

## 5. 工具上线后的维护

### 修改运行配置

在工具的“运行配置”中可以维护上游根地址、认证方式、Token、健康检查、限流、超时、TLS、重试和网络隔离信息。

- 修改上游地址或认证后应先执行连接测试。
- Token 只能替换，不能从平台页面读取原值。
- 保存运行配置会形成历史版本；发生错误时可按版本回滚。
- 配置保存使用版本控制。若有其他管理员刚修改过配置，应先刷新并重新确认后再保存。

### 同步接口文档

工具服务升级接口文档后，使用“同步差异”。同步会识别新增、删除和变更项目，但不会直接把变化开放给用户。

处理原则：

- 新增接口：按首次接入流程审核。
- 已发布接口变更：确认参数、响应、路径和权限变化是否会影响用户程序。
- 删除接口：先通知使用方并确认替代方案，再在平台处理。
- 高风险或不明确变化：阻断或延后，向服务提供方补充说明。

### 单接口处理

单接口详情可用于调整对外说明、Gateway 路径、请求规则、限流、超时、风险标记和访问策略，也可执行排除、阻断或发布操作。所有会影响对外服务的操作都应记录业务原因，并在审计日志中复核。

### 停用与恢复

当工具服务维护、存在安全问题或不应继续提供服务时，将工具停用。停用后，即使接口曾经发布，Gateway 也会拒绝对该工具的调用。

恢复前应确认：服务可达、上游认证正确、接口治理仍符合业务要求，并使用测试 Key 完成最小调用验证。

## 6. 用户管理

### 审批公开注册用户

公开注册用户需要完成邮箱验证后才进入待审批状态。管理员在“用户管理”中查看申请信息并选择：

- 批准：用户获得登录、创建 Key 和调用已发布接口的资格。
- 拒绝：用户不能登录和调用；应按业务规则填写或告知原因。
- 停用：用于已获批但暂时不应继续使用平台的账号；已有会话和 Key 会失效。
- 启用：恢复此前停用的账号。

### 批量导入与临时密码

管理员可以通过 CSV 批量开通用户。导入用户默认需要先修改临时密码；在其完成改密前，不应视为可调用 Gateway 的正常用户。

### 用户限流与 Key 处置

管理员可以对单个用户设置每分钟请求上限。设置为 `0` 表示不额外施加用户级限制，工具自身的限流仍会生效。

当用户报告 Key 泄露、异常调用或长期不再使用时，可在用户详情或 Key 管理中禁用该 Key。管理员只能看到 Key 前缀、状态、到期时间和使用情况，不能查看完整 Key。

## 7. 平台设置、监控和审计

### 平台设置

平台设置用于维护：

- 站点名称、说明和品牌图。
- 公开 Gateway 根地址。它决定用户文档中展示的对外入口，不会自动配置 DNS、TLS、反向代理或服务器。
- 新用户默认每分钟请求上限。
- SMTP 邮件配置、连通性测试和测试邮件。

未配置 SMTP 时，邮件验证、找回密码和邮箱变更会关闭。管理员创建用户、CSV 导入和临时密码流程不依赖 SMTP。

### 监控与排障

用户报障时，首先索取 request_id，然后在“监控告警”中定位同一次请求。重点查看：工具、接口、状态码、错误码、上游状态、耗时、请求/响应流量和时间。

常见判断：

| 现象 | 优先排查 |
| --- | --- |
| 401 | 用户状态、Key 是否有效、是否已过期或被禁用 |
| 403 | Key 作用范围、访问策略或资源归属 |
| 404 | 路由是否已发布，路径和方法是否正确 |
| 413 或 415 | 请求大小、响应大小或 Content-Type 是否符合接口策略 |
| 429 | 用户级或 Key/工具级限流 |
| 502 | 上游不可达、返回异常或资源策略无法安全处理 |
| 503 | 工具停用、未配置上游或服务暂不可用 |
| 504 | 上游响应超时 |

当前“告警”主要是查询和统计视图；管理员仍需结合监控、工具健康状态和外部运维流程处理问题。

### 审计日志

用户审批、工具配置、接口治理、发布、差异处理、Key 管理等关键管理员操作会形成审计记录。发生争议、异常或变更复盘时，先按时间、操作人、对象或 request_id 查询审计日志。

## 8. 有条件启用的任务与文件能力

任务、文件和制品能力并非每个工具默认拥有。只有工具配置了相应任务适配和文件契约，并且运行文件 worker 后，用户侧才可能看到任务状态、日志、文件清单、下载或删除功能。

管理员处理相关问题时，应先确认：工具是否已配置此能力、对应接口是否已发布、文件 worker 是否正常运行、文件状态是否为可下载，以及资源是否属于当前用户。

## 9. 管理员发布检查清单

- [ ] 工具名称、slug 和用户说明已确认。
- [ ] 上游地址属于允许连接范围，健康检查通过。
- [ ] 上游认证已正确配置，凭证没有写入公开说明。
- [ ] OpenAPI/Swagger 导入成功，所有候选项已有处理结果。
- [ ] 每个用户可见接口的访问策略、资源规则、超时和限流已确认。
- [ ] 高风险、管理、调试和删除接口已阻断或排除。
- [ ] 发布校验通过，用户文档中已看到正确 Gateway 路径。
- [ ] 测试 Key 调用成功，并能在监控中按 request_id 找到记录。
- [ ] 用户侧不展示真实上游地址、Token 或内部路径。
- [ ] 关键操作和业务原因可在审计日志中追溯。
