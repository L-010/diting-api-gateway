## 1. 平台概述

### 1.1 平台是什么

API Gateway 开发者平台是一个集中管理和发布 API 服务的统一入口系统。它将多个独立部署在不同服务器上的专业工具（例如科研计算工具、数据处理服务），通过统一的 Gateway 对外提供 API 调用能力。

**核心价值**：

- **统一入口**：用户只需一个平台账号和一把 API Key，即可调用所有已发布的工具接口
- **安全隔离**：用户不直接接触工具服务器地址和机器凭证
- **集中治理**：管理员统一审核接口、设置权限策略、监控调用
- **资源隔离**：自动保护用户资源，防止越权访问

### 1.2 平台不是什么

- **不是工具开发平台**：平台不负责开发或部署工具本身，工具由专业团队独立开发和部署
- **不是通用代理**：平台只转发已审核和发布的接口，不支持任意 URL 转发
- **不是自动化系统**：接口导入后不会自动发布，必须经过管理员审核

### 1.3 工作原理

```
独立工具服务器
    ↓
管理员接入工具 → 导入接口文档 → 审核治理 → 发布路由
    ↓
用户获取 API Key → 调用统一 Gateway
    ↓
Gateway：鉴权 → 限流 → 权限校验 → 转发到工具服务器
    ↓
返回结果 + 记录调用日志
```

### 1.4 重要边界

**用户看到的**：
- 统一的 Gateway 地址（例如 `https://api.example.com`）
- 工具名称和接口说明
- Gateway 路径（例如 `/gateway/data-tool/query`）
- 标准的请求参数和响应格式

**用户看不到的**（必须保护）：
- 工具服务器的真实 IP 地址和端口
- 上游服务的认证 Token
- 服务器内部路径映射
- 其他用户的资源和数据

## 2. 管理员角色与职责

### 2.1 管理员的核心工作

| 工作类型 | 具体内容 | 频率 |
| --- | --- | --- |
| 用户管理 | 审批注册申请、批量导入用户、停用/启用账号、处理异常 Key | 每日或按需 |
| 工具接入 | 新建工具、配置上游服务、导入接口文档、审核接口 | 按项目上线 |
| 接口治理 | 确认访问策略、设置资源规则、识别风险接口、发布路由 | 每次新工具或接口变更 |
| 监控排障 | 查看调用记录、分析错误、处理用户报障、查看告警 | 每日巡检或按需 |
| 平台维护 | 配置站点信息、邮件服务、限流规则、健康检查 | 初始配置或调整时 |
| 审计复盘 | 查看操作日志、追溯变更、合规检查 | 定期或应急响应 |

### 2.2 管理员与技术团队的协作

管理员不需要掌握所有技术细节，但需要与以下角色协作：

| 角色 | 提供什么 | 管理员如何使用 |
| --- | --- | --- |
| 工具开发团队 | 工具服务器地址、认证 Token、OpenAPI 文档、接口说明 | 接入工具并配置上游服务 |
| 运维/DevOps | 服务器白名单、网络策略、健康检查地址 | 确认连接可达性 |
| 安全团队 | 风险评估、访问策略建议、合规要求 | 审核接口并设置权限 |
| 业务负责人 | 工具用途、用户范围、资源归属规则 | 确认开放范围和策略 |

### 2.3 管理员权限说明

管理员在平台中拥有最高权限，但仍有以下限制：

**可以做的**：
- 审批、停用、启用用户账号
- 接入、配置、发布、停用工具
- 查看所有用户的调用记录（脱敏）
- 禁用用户的 API Key（看不到完整 Key）
- 查看和导出监控数据
- 查看审计日志

**不能做的**：
- 查看用户的完整 API Key（只能看前缀）
- 查看已保存的上游 Token 明文（只能替换）
- 以其他用户身份登录（除非明确创建测试账号）
- 访问用户程序的源代码或配置

## 3. 术语解释

### 3.1 工具相关术语

| 术语 | 通俗解释 | 技术说明 |
| --- | --- | --- |
| 工具 (Tool) | 平台接入的一个独立服务 | 例如某个数据分析工具、计算服务 |
| 工具 slug | 工具的唯一短名称 | 只能包含小写字母、数字、短横线，创建后不可修改 |
| 上游服务 | 工具实际运行的服务器 | 例如 `http://192.168.1.100:8080` |
| 上游根地址 | 平台连接工具的入口 | 必须是 http/https 根地址，不能包含路径 |
| 健康检查路径 | 测试服务是否可达的接口 | 例如 `/health` 或 `/api/status` |
| 上游 Token | 平台访问工具时的凭证 | 平台加密保存，只能替换，不能查看 |

### 3.2 接口与路由术语

| 术语 | 通俗解释 | 技术说明 |
| --- | --- | --- |
| 接口 (Endpoint) | 工具提供的一项具体能力 | 例如"查询数据"、"创建任务" |
| Gateway 路径 | 用户调用时使用的地址 | 例如 `/gateway/data-tool/query` |
| 上游路径 | 工具服务器内部的路径 | 例如 `/api/v1/query`，用户看不到 |
| 路由 (Route) | Gateway 到上游的完整映射规则 | 包含方法、路径、策略、限流等 |
| 已发布路由 | 用户可以调用的路由 | 只有发布后才能通过 Gateway 调用 |
| 候选接口 | 已导入但未发布的接口 | 需要审核后才能发布 |

### 3.3 访问控制术语

| 术语 | 通俗解释 | 适用场景 |
| --- | --- | --- |
| authenticated | 所有已审批用户都可以调用 | 公开的计算、查询服务 |
| owner | 只能访问自己创建的资源 | 个人任务、文件、数据集 |
| shared | 所有用户看到相同的共享数据 | 全局配置、公共数据列表 |
| admin_only | 只有管理员可以调用 | 内部管理、诊断接口 |

### 3.4 用户状态术语

| 术语 | 含义 | 用户能做什么 |
| --- | --- | --- |
| 待审批 (pending) | 已注册但未批准 | 不能登录 |
| 已审批 (approved) | 管理员已批准 | 可以登录和调用 API |
| 已拒绝 (rejected) | 管理员拒绝申请 | 不能登录，看到拒绝原因 |
| 已停用 (disabled) | 账号被暂停使用 | 不能登录，已有 Key 失效 |
| 必须修改密码 | 使用临时密码的账号 | 登录后必须先改密码 |

### 3.5 监控与排障术语

| 术语 | 含义 | 用途 |
| --- | --- | --- |
| request_id | 每次调用的唯一编号 | 排查问题的关键信息 |
| 调用记录 | Gateway 请求的历史记录 | 查看谁在什么时候调用了什么 |
| 状态码 | HTTP 响应状态 | 200 成功，4xx 客户端错误，5xx 服务器错误 |
| 错误码 | 平台定义的错误类型 | 例如 `INVALID_API_KEY`、`PERMISSION_DENIED` |
| 限流 | 请求频率限制 | 防止滥用和保护服务器 |

## 4. 首次登录与平台配置

### 4.1 首次登录

**步骤 1：访问平台管理后台**

打开浏览器，访问平台地址（例如 `https://your-platform.com`），点击右上角"登录"。

**步骤 2：使用管理员账号登录**

输入初始管理员账号和密码（由部署团队提供）。

> **安全提示**：首次登录后，请立即修改默认密码。进入"账户设置" → "修改密码"。

**步骤 3：查看管理总览**

登录后进入"管理总览"页面，显示：
- 待审批用户数量
- 已接入工具数量
- 近期调用统计
- 需要关注的告警

### 4.2 平台基础配置

在首次使用前，需要完成平台的基础配置。

#### 4.2.1 站点信息配置

**操作路径**：左侧菜单 → 平台设置 → 站点信息

**配置项说明**：

| 配置项 | 说明 | 示例 |
| --- | --- | --- |
| 站点名称 | 平台的对外名称 | "科研工具 API 平台" |
| 站点说明 | 简要介绍平台用途 | "为科研人员提供统一的工具调用入口" |
| Gateway 根地址 | 用户调用时使用的公网地址 | `https://api.example.com` |
| 品牌图标 | 平台 Logo（可选） | 上传 PNG/SVG 文件 |

> **重要**：Gateway 根地址是用户在接口文档中看到的入口地址。配置后不会自动修改 DNS、TLS 证书或反向代理，这些需要运维团队单独配置。

#### 4.2.2 邮件服务配置（可选）

**操作路径**：左侧菜单 → 平台设置 → 邮件配置

如果配置了邮件服务，平台可以发送：
- 注册验证邮件
- 密码重置邮件
- Key 临期提醒
- 账号状态变更通知

**配置项说明**：

| 配置项 | 说明 | 示例 |
| --- | --- | --- |
| SMTP 服务器 | 邮件服务器地址 | `smtp.example.com` |
| SMTP 端口 | 通常为 25、465 或 587 | `587` |
| 发件人邮箱 | 平台发送邮件的地址 | `noreply@example.com` |
| 发件人名称 | 邮件显示的发件人 | "API 平台" |
| 用户名 | SMTP 认证用户名 | `apiplatform@example.com` |
| 密码 | SMTP 认证密码 | `********` |
| 使用 TLS | 是否启用加密连接 | 推荐启用 |

**配置后测试**：

点击"发送测试邮件"，输入一个测试邮箱地址，检查能否收到邮件。

> **注意**：如果不配置邮件服务，公开注册验证、找回密码和邮箱变更功能会关闭。但管理员创建用户、CSV 导入和临时密码流程不受影响。

#### 4.2.3 默认限流配置

**操作路径**：左侧菜单 → 平台设置 → 限流规则

**配置项说明**：

| 配置项 | 说明 | 推荐值 |
| --- | --- | --- |
| 新用户默认限流 | 新注册用户的每分钟请求上限 | 60 次/分钟 |

> **说明**：此配置是新用户的默认值，可以在用户管理中为单个用户单独设置。设置为 `0` 表示不额外限制（工具自身的限流仍会生效）。

### 4.3 管理员界面导航

登录后，左侧菜单包含以下主要入口：

| 菜单项 | 用途 | 何时使用 |
| --- | --- | --- |
| 管理总览 | 查看整体状况和待办事项 | 每日巡检 |
| 用户管理 | 审批、导入、停用用户 | 处理用户申请 |
| 工具管理 | 接入、配置、发布工具 | 新工具上线或变更 |
| 监控告警 | 查看调用统计和问题 | 日常监控或排障 |
| 审计日志 | 查看管理操作记录 | 合规检查或追溯 |
| 平台设置 | 修改全局配置 | 初始配置或调整 |

## 5. 用户管理

### 5.1 审批注册用户

当有用户通过公开页面注册时，管理员需要审批。

**操作路径**：左侧菜单 → 用户管理 → 待审批用户

**审批流程**：

**步骤 1：查看申请信息**

页面显示所有待审批的用户，包含：
- 用户名
- 邮箱地址
- 显示名称
- 申请说明（用户填写的使用目的）
- 申请时间

**步骤 2：核对信息**

检查以下内容：
- 邮箱是否为有效的企业或机构邮箱
- 申请说明是否合理
- 是否有重复申请

**步骤 3：做出决定**

点击用户行右侧的操作按钮：

**批准**：
1. 点击"批准"按钮
2. 用户状态变为"已审批"，可以登录平台
3. 如果配置了邮件服务，用户会收到批准通知

**拒绝**：
1. 点击"拒绝"按钮
2. 在弹出的对话框中填写拒绝原因
3. 用户尝试登录时会看到拒绝原因

> **提示**：批准后，用户可以登录、创建 API Key 并调用已发布的接口。建议定期审查用户列表，及时处理申请。

### 5.2 批量导入用户（CSV）

对于需要批量开通的用户（例如培训班学员、项目团队成员），可以使用 CSV 导入。

**操作路径**：左侧菜单 → 用户管理 → 批量导入

**步骤 1：准备 CSV 文件**

创建一个 UTF-8 编码的 CSV 文件，包含以下列：

| 列名 | 是否必填 | 说明 | 示例 |
| --- | --- | --- | --- |
| username | 必填 | 用户名，不能重复 | `zhangsan` |
| password | 必填 | 临时密码，至少 12 位 | `TempPass123!` |
| display_name | 可选 | 显示名称 | `张三` |
| email | 可选 | 邮箱地址 | `zhangsan@example.com` |

**CSV 文件示例**：

```csv
username,password,display_name,email
zhangsan,TempPass123!,张三,zhangsan@example.com
lisi,TempPass456!,李四,lisi@example.com
wangwu,TempPass789!,王五,wangwu@example.com
```

**步骤 2：上传文件**

1. 点击"选择文件"按钮
2. 选择准备好的 CSV 文件
3. 点击"导入"

**步骤 3：查看导入结果**

页面会显示：
- 成功导入的用户数量
- 失败的行及原因（例如用户名已存在、密码不符合要求）

**导入用户的特点**：

- 默认状态为"已审批"，可以立即登录
- 首次登录时会强制要求修改临时密码
- 修改密码前不能使用平台功能

> **安全提示**：
> - CSV 文件中包含明文密码，导入后请立即删除文件
> - 不要通过邮件或聊天发送 CSV 文件
> - 告知用户首次登录后必须修改密码

### 5.3 查看和管理用户

**操作路径**：左侧菜单 → 用户管理 → 所有用户

**用户列表显示**：

| 列 | 说明 |
| --- | --- |
| 用户名 | 登录名称 |
| 显示名称 | 对外显示的名字 |
| 邮箱 | 注册邮箱 |
| 状态 | 待审批/已审批/已停用/已拒绝 |
| 注册时间 | 账号创建时间 |
| 最后登录 | 最近一次登录时间 |
| API Key 数量 | 该用户创建的 Key 数量 |

**筛选和搜索**：

- 按状态筛选：只看待审批/已审批/已停用用户
- 搜索：输入用户名或邮箱快速查找

**查看用户详情**：

点击用户行，展开详情面板，可以看到：
- 基本信息：用户名、邮箱、显示名称、注册时间
- 状态信息：审批状态、是否停用、必须改密标记
- API Key 列表：该用户的所有 Key（只显示前缀和状态）
- 调用统计：近期调用量、成功率、错误次数
- 限流设置：该用户的每分钟请求上限

### 5.4 停用和启用用户

**何时需要停用用户**：

- 用户离职或项目结束
- 发现异常调用或滥用行为
- 用户长期不使用需要清理
- 安全事件需要临时限制访问

**停用操作**：

1. 进入用户详情页面
2. 点击"停用用户"按钮
3. 填写停用原因（用户会看到）
4. 确认停用

**停用后的效果**：

- 用户无法登录平台
- 用户的所有 API Key 立即失效
- 正在进行的调用会返回 401 错误
- 用户尝试登录时会看到停用原因

**启用操作**：

1. 找到已停用的用户
2. 点击"启用用户"按钮
3. 用户恢复正常使用

> **注意**：停用和启用都会记录在审计日志中。

### 5.5 管理用户的 API Key

**操作路径**：用户详情 → API 密钥标签

**查看用户的 Key 列表**：

| 列 | 说明 |
| --- | --- |
| Key 前缀 | 例如 `agw_1a2b3c`，用于识别 |
| 标签 | 用户创建时填写的名称 |
| 状态 | 可用/已过期/已禁用 |
| 创建时间 | Key 创建时间 |
| 过期时间 | Key 失效时间（如果有） |
| 最后使用时间 | 最近一次成功调用的时间 |

**禁用用户的 Key**：

当发现以下情况时，管理员可以禁用用户的 Key：

- 用户报告 Key 泄露
- 发现异常调用模式
- Key 被用于攻击或滥用
- 用户长期未使用该 Key

**操作步骤**：

1. 在用户的 Key 列表中找到问题 Key
2. 点击"禁用"按钮
3. 填写禁用原因
4. 确认禁用

**禁用后**：

- 该 Key 立即失效
- 使用该 Key 的调用会返回 401 错误
- 用户在自己的 Key 列表中看到"已禁用"状态
- 用户可以创建新 Key 替换

> **重要**：管理员只能看到 Key 前缀，看不到完整 Key。如果用户忘记了完整 Key，只能创建新 Key。

### 5.6 设置用户限流

**操作路径**：用户详情 → 限流设置

为单个用户设置每分钟请求上限，覆盖平台默认值。

**何时需要调整**：

- 用户业务需求高，需要更高额度
- 用户频繁触发限流，需要评估后提高
- 测试用户需要临时提高额度
- 发现滥用需要降低额度

**操作步骤**：

1. 进入用户详情页面
2. 找到"限流设置"区域
3. 输入新的每分钟请求上限（例如 `120`）
4. 点击"保存"

**特殊值说明**：

- 设置为 `0`：不额外限制该用户（工具自身限流仍生效）
- 不设置：使用平台默认值

> **提示**：调整限流前，先查看用户的调用统计，了解实际需求。

## 6. 工具接入完整流程

接入一个新工具是管理员最重要的工作之一。本节详细说明从准备到发布的完整流程。

### 6.1 接入前的准备

在开始接入前，向工具开发团队或技术同事收集以下信息：

**检查清单**：

- [ ] 工具的业务名称和用途说明
- [ ] 工具的唯一短名称（slug，例如 `data-tool`）
- [ ] 工具服务器的内部地址（例如 `http://192.168.1.100:8080`）
- [ ] 工具服务器的健康检查路径（例如 `/health`）
- [ ] 平台访问工具时的认证方式（无认证/Bearer Token/API Key）
- [ ] 如果需要认证，提供 Token 或 API Key 的值
- [ ] 工具的 OpenAPI/Swagger 文档（URL、文件或文本）
- [ ] 哪些接口可以对用户开放
- [ ] 哪些接口是内部管理或调试用途
- [ ] 资源（任务、文件、数据集）的归属规则

**确认前置条件**：

- [ ] 工具服务器的 IP 地址在平台的允许列表中
- [ ] 平台可以通过网络访问工具服务器
- [ ] 工具服务已经部署并可以正常运行
- [ ] OpenAPI 文档准确描述了接口的参数和响应

> **重要**：如果工具服务器不在允许列表中，联系运维团队将其加入 `ALLOWED_UPSTREAM_HOSTS` 配置。

### 6.2 新建工具

**操作路径**：左侧菜单 → 工具管理 → 新建工具

平台提供"新建工具向导"，按步骤引导完成配置。

#### 步骤 1：基本信息

**填写内容**：

| 字段 | 说明 | 示例 | 注意事项 |
| --- | --- | --- | --- |
| 工具名称 | 对外显示的名称 | "数据分析工具" | 使用业务名称，用户会看到 |
| 工具 slug | 唯一短名称 | `data-tool` | 只能小写字母、数字、短横线；创建后不可修改 |
| 工具说明 | 用途和适用场景 | "提供数据清洗、统计和可视化能力" | 详细说明工具能做什么 |

**slug 命名建议**：

- ✅ 使用有意义的名称：`data-tool`、`image-processor`、`report-generator`
- ✅ 多个单词用短横线连接：`data-analysis-tool`
- ❌ 避免使用代号或缩写：`tool1`、`dap`、`xyz`
- ❌ 不要包含版本号：`data-tool-v2`（版本升级应保持 slug 不变）

> **重要**：slug 创建后不可修改，会成为 Gateway 路径的一部分（例如 `/gateway/data-tool/...`）。

#### 步骤 2：上游服务配置

**填写内容**：

| 字段 | 说明 | 示例 | 注意事项 |
| --- | --- | --- | --- |
| 上游根地址 | 工具服务器的入口地址 | `http://192.168.1.100:8080` | 必须是 http/https 根地址，不能包含路径 |
| 健康检查路径 | 测试连接的接口 | `/health` 或 `/api/status` | 由工具开发团队提供 |

**上游根地址格式要求**：

- ✅ 正确：`http://192.168.1.100:8080`
- ✅ 正确：`https://tool-server.internal.com`
- ❌ 错误：`http://192.168.1.100:8080/api`（包含路径）
- ❌ 错误：`http://192.168.1.100:8080?token=xxx`（包含查询参数）

#### 步骤 3：服务端认证配置

选择平台访问工具服务器时的认证方式：

| 认证方式 | 说明 | 何时使用 |
| --- | --- | --- |
| 无认证 | 工具服务器不需要认证 | 内部网络，服务器不对外开放 |
| Bearer Token | 使用 `Authorization: Bearer {token}` 请求头 | 工具使用 OAuth2 或 JWT |
| Header API Key | 使用自定义请求头（例如 `X-API-Key`） | 工具使用自己的 API Key 认证 |

**如果选择 Bearer Token**：

1. 输入 Token 的值（由工具开发团队提供）
2. Token 会加密保存在平台数据库中
3. 保存后只能替换，不能查看原值

**如果选择 Header API Key**：

1. 输入 Header 名称（例如 `X-Tool-API-Key`）
2. 输入 Key 的值
3. Key 会加密保存

> **安全提示**：
> - 上游 Token/Key 只在管理员页面配置，永远不会出现在用户文档中
> - 保存后无法查看原值，只能替换
> - 定期轮换 Token 以提高安全性

#### 步骤 4：运行参数配置

| 配置项 | 说明 | 推荐值 | 注意事项 |
| --- | --- | --- | --- |
| 工具级限流 | 单把 Key 调用该工具的每分钟上限 | 60 次/分钟 | 根据工具承载能力设置 |
| 请求超时 | Gateway 等待上游响应的最长时间 | 30 秒 | 慢任务应使用异步模式，不能只靠延长超时 |
| 是否允许重试 | 上游失败时是否自动重试 | 查询接口可以，写操作不建议 | 重试可能导致重复操作 |
| TLS 验证 | 是否验证上游服务器的 TLS 证书 | 推荐启用 | 测试环境可以临时关闭 |

#### 步骤 5：保存草稿

点击"保存草稿"按钮。此时：

- 工具配置已保存，但尚未对用户开放
- 可以继续配置或导入接口
- 用户在工具列表中看不到该工具

### 6.3 连接测试

保存草稿后，必须测试平台能否连接到工具服务器。

**操作步骤**：

1. 在工具详情页面，找到"连接测试"区域
2. 点击"执行健康检查"按钮
3. 等待测试结果

**测试结果说明**：

**成功**：
- 显示绿色提示"连接成功"
- 显示响应时间（例如 50ms）
- 可以继续导入接口

**失败**：
- 显示红色错误提示
- 显示具体错误原因

**常见失败原因及解决方法**：

| 错误提示 | 可能原因 | 如何解决 |
| --- | --- | --- |
| "连接超时" | 网络不通，服务器未启动 | 检查服务器地址、防火墙、服务是否运行 |
| "连接被拒绝" | 端口错误，服务未监听 | 检查端口号，确认服务已启动 |
| "健康检查路径返回 404" | 健康检查路径错误 | 向开发团队确认正确路径 |
| "认证失败" | Token 或 API Key 错误 | 检查认证配置，向开发团队确认凭证 |
| "不在允许列表中" | 服务器地址未加入白名单 | 联系运维团队添加到 `ALLOWED_UPSTREAM_HOSTS` |

> **提示**：连接成功不代表所有业务接口都能正常工作，只表示平台可以到达工具服务器。后续仍需测试具体接口。

### 6.4 导入 OpenAPI/Swagger 文档

连接测试成功后，导入工具的接口文档。

**操作路径**：工具详情 → 接口管理 → 导入 API 文档

**导入方式选择**：

| 方式 | 说明 | 何时使用 |
| --- | --- | --- |
| 从上游默认地址获取 | 平台自动访问常见文档地址 | 工具提供标准 OpenAPI 端点 |
| 从指定 URL 获取 | 输入文档的完整 URL | 文档在非标准路径 |
| 上传文件 | 上传 JSON 或 YAML 文件 | 开发团队提供文档文件 |
| 粘贴文本 | 复制粘贴文档内容 | 从邮件或文档中获取内容 |

**方式 1：从上游默认地址获取**

1. 选择"从上游默认地址获取"
2. 点击"开始导入"
3. 平台会自动尝试以下地址：
   - `/openapi.json`
   - `/swagger.json`
   - `/api/v1/openapi.json`
   - `/docs/openapi.json`

**方式 2：从指定 URL 获取**

1. 选择"从指定 URL 获取"
2. 输入文档 URL（例如 `http://192.168.1.100:8080/api/openapi.json`）
3. 点击"开始导入"

**方式 3：上传文件**

1. 选择"上传文件"
2. 点击"选择文件"
3. 选择 `.json` 或 `.yaml` 文件（最大 2 MB）

**方式 4：粘贴文本**

1. 选择"粘贴文本"
2. 将 OpenAPI/Swagger JSON 或 YAML 内容粘贴到文本框
3. 点击"开始导入"

**导入处理过程**：

1. 平台解析文档，识别所有接口
2. 分析每个接口的方法、路径、参数、请求体、响应
3. 识别潜在风险（管理接口、删除操作、全局列表等）
4. 生成访问策略建议
5. 创建导入批次记录

**导入结果**：

- 识别到的接口数量
- 新增接口数量
- 变更接口数量
- 风险提示数量
- 导入批次编号

**常见导入错误**：

| 错误提示 | 原因 | 解决方法 |
| --- | --- | --- |
| "文档格式错误" | 不是有效的 OpenAPI/Swagger | 检查文档格式，向开发团队确认 |
| "不支持的版本" | 文档版本过旧或过新 | 平台支持 OpenAPI 3.0/3.1 和 Swagger 2.0 |

**候选接口列表显示**：

| 列 | 说明 |
| --- | --- |

| 请求方法 | GET / POST / PUT / PATCH / DELETE / HEAD |
| Gateway 路径 | 用户调用时使用的路径（可编辑） |
| 上游路径 | 工具服务器内部路径（不对用户展示） |
| 风险等级 | 低/中/高/阻断 |
| 状态 | 待处理/已放行/已排除/已阻断/已发布 |

**风险等级说明**：

| 风险等级 | 含义 | 典型示例 |
| --- | --- | --- |
| 低 | 普通查询接口，风险可控 | 查询数据、下载文件 |
| 中 | 创建或修改操作，需要确认权限 | 创建任务、更新配置 |
| 高 | 敏感操作，需要特别审核 | 批量修改、导出数据 |

- 批量删除或清空操作
- 全局资源列表接口（例如 `/users`、`/tasks`，没有用户 ID 过滤）

> **重要**：阻断级接口不能自动发布，必须由管理员显式放行或确认排除。

### 6.6 接口审核与决策

导入候选接口后，需要逐个审核并做出决策。

**操作路径**：工具详情 → 接口管理 → 候选接口 → 点击某个接口

**审核步骤**：

**步骤 1：理解接口用途**

查看接口详情页面的以下信息：
- 接口名称和描述
- 请求方法和路径
- 请求参数：路径参数、查询参数、请求体
- 响应格式和示例
- 从路径和参数判断该接口的业务含义

**步骤 2：判断是否对用户开放**

回答以下问题：

1. **这个接口是否应该对普通用户开放？**
   - 是业务功能 → 继续审核
   - 是内部管理/调试 → 阻断或排除

2. **这个接口是否安全？**
   - 查询类接口 → 相对安全
   - 创建/修改类 → 需要权限控制
   - 删除类 → 高风险，谨慎开放

3. **这个接口操作什么资源？**
   - 用户自己的资源 → 需要 `owner` 策略
   - 所有用户共享的数据 → 需要 `shared` 策略
   - 不涉及资源 → `authenticated` 即可

**步骤 3：做出决策**

点击以下按钮之一：

| 决策 | 含义 | 何时使用 |
| --- | --- | --- |
| 放行 | 同意发布给用户 | 审核通过的业务接口 |
| 排除 | 本次不纳入平台 | 未来可能开放，暂时不发布 |
| 阻断 | 明确禁止发布 | 高危接口，不应对外开放 |
| 延后 | 需要更多信息再决定 | 不确定，需要咨询开发团队 |

**决策后的状态流转**：

```
待处理 → 放行 → 配置访问策略 → 发布
      → 排除 → 不进入发布流程
      → 阻断 → 明确禁止
      → 延后 → 保持待处理状态
```

**批量决策**：

如果有多个相似接口，可以批量处理：

1. 在候选接口列表中勾选多个接口
2. 点击"批量操作"按钮
3. 选择"批量放行"、"批量排除"或"批量阻断"
4. 填写统一的处理原因
5. 确认操作

> **提示**：批量操作适合处理明显的低风险接口（例如多个查询接口）。对于敏感接口，建议逐个审核。

## 7. 接口治理与访问策略

### 7.1 访问策略详解

每个放行的接口必须设置访问策略，决定谁可以调用、能访问什么资源。

#### 7.1.1 authenticated（平台用户可调用）

**适用场景**：
- 不涉及个人资源的普通服务
- 公开的计算、转换、查询功能
- 工具类接口

**示例接口**：
- 数据格式转换：`POST /gateway/converter/json-to-csv`
- 公开数据查询：`GET /gateway/geoinfo/earthquake-list?region=CN`
- 算法计算：`POST /gateway/calculator/statistical-analysis`

**权限控制**：
- 所有已审批的用户都可以调用
- 不检查资源归属
- 通过限流保护服务

**配置要点**：
- 确认接口不返回其他用户的私有数据
- 设置合理的限流额度
- 如果接口消耗资源较大（例如复杂计算），考虑降低限流

#### 7.1.2 owner（仅资源创建者）

**适用场景**：
- 用户的任务、文件、数据集
- 个人配置、偏好设置
- 用户上传的内容

**示例接口**：
- 查看我的任务：`GET /gateway/data-tool/tasks/{task_id}`
- 下载我的文件：`GET /gateway/data-tool/files/{file_id}/download`
- 删除我的数据集：`DELETE /gateway/data-tool/datasets/{dataset_id}`
- 我的任务列表：`GET /gateway/data-tool/tasks`（自动过滤）

**权限控制**：
- 调用前检查资源是否属于当前用户
- 如果资源不属于该用户，返回 403 错误
- 列表接口只返回该用户的资源

**配置资源规则**：

当选择 `owner` 策略时，需要配置资源规则，告诉平台如何判断资源归属。

**资源规则类型**：

| 规则类型 | 说明 | 配置示例 |
| --- | --- | --- |
| 路径参数提取 | 从 URL 路径中提取资源 ID | `/tasks/{task_id}` → `task_id` |
| 查询参数提取 | 从查询参数中提取资源 ID | `?task_id=xxx` → `task_id` |
| 请求体提取 | 从 JSON 请求体中提取资源 ID | `{"task_id": "xxx"}` → `task_id` |
| 响应体登记 | 从成功响应中登记新资源 | `{"id": "task_123"}` → 登记为当前用户所有 |
| 列表过滤 | 过滤响应列表，只返回用户资源 | `{"items": [...]}` → 只保留属于用户的项 |

**配置步骤**：

**示例 1：查看任务详情**

接口：`GET /gateway/data-tool/tasks/{task_id}`

1. 选择"路径参数提取"
2. 参数名：`task_id`
3. 资源类型：`task`
4. 校验时机：调用前
5. 保存规则

平台会在调用前检查 `task_id` 对应的任务是否属于当前用户。

**示例 2：创建任务**

接口：`POST /gateway/data-tool/tasks`

1. 选择"响应体登记"
2. JSONPath：`$.id`（从响应的 `{"id": "task_123"}` 中提取 ID）
3. 资源类型：`task`
4. 登记时机：调用成功后
5. 保存规则

平台会在任务创建成功后，将返回的 `id` 登记为当前用户所有。

**示例 3：我的任务列表**

接口：`GET /gateway/data-tool/tasks`

1. 选择"列表过滤"
2. 列表路径：`$.items`（响应格式为 `{"items": [...]}`）
3. 资源 ID 字段：`id`（每个任务对象包含 `id` 字段）
4. 资源类型：`task`
5. 保存规则

平台会自动过滤响应，只返回属于当前用户的任务。

> **重要**：资源规则必须准确，否则会导致用户无法访问自己的资源，或者能访问他人的资源。

#### 7.1.3 shared（平台用户共享）

**适用场景**：
- 全局配置数据
- 公共参考数据
- 所有用户都能看到的列表

**示例接口**：
- 获取系统配置：`GET /gateway/data-tool/config`
- 公共数据字典：`GET /gateway/data-tool/dict/regions`
- 全局统计信息：`GET /gateway/data-tool/stats`

**权限控制**：
- 所有已审批用户看到相同的数据
- 不进行资源归属校验
- 不过滤响应内容

**使用限制**：
- 必须由管理员明确确认数据可以共享
- 发布时需要填写审计原因，说明为什么这个接口可以共享
- 不应用于包含用户隐私的数据

> **警告**：`shared` 模式不会保护用户隐私。只对确认可以公开的数据使用此策略。

#### 7.1.4 admin_only（仅管理员）

**适用场景**：
- 平台管理功能
- 内部诊断接口
- 系统维护操作

**示例接口**：
- 查看所有用户：`GET /gateway/data-tool/admin/users`
- 系统诊断：`GET /gateway/data-tool/admin/diagnostics`
- 清理缓存：`POST /gateway/data-tool/admin/clear-cache`

**权限控制**：
- 只有管理员角色可以调用
- 普通用户文档中不显示这些接口
- 普通用户调用时返回 404（而不是 403，防止接口被发现）

**使用建议**：
- 尽量不要通过 Gateway 暴露管理接口
- 管理操作应直接在服务器上执行
- 如果必须通过 Gateway，务必使用 `admin_only`

### 7.2 资源规则配置实战

以下是几个常见场景的资源规则配置示例。

#### 场景 1：查询单个资源

**接口**：`GET /gateway/data-tool/datasets/{dataset_id}`

**业务含义**：查看数据集详情，用户只能查看自己的数据集。

**资源规则配置**：

```
规则类型：路径参数提取
参数名：dataset_id
资源类型：dataset
校验时机：调用前
父资源：无
```

**执行逻辑**：
1. 用户调用 `GET /gateway/data-tool/datasets/ds_123`
2. 平台提取 `dataset_id = ds_123`
3. 查询数据库：`ds_123` 是否属于当前用户
4. 如果是 → 转发请求
5. 如果否 → 返回 403 错误

#### 场景 2：创建资源并登记

**接口**：`POST /gateway/data-tool/tasks`

**业务含义**：创建分析任务，任务创建后应属于当前用户。

**资源规则配置**：

```
规则类型：响应体登记
JSONPath：$.task.id
资源类型：task
登记时机：调用成功后（状态码 200-299）
```

**响应示例**：
```json
{
  "task": {
    "id": "task_abc123",
    "name": "数据分析任务",
    "status": "pending"
  }
}
```

**执行逻辑**：
1. 用户调用 `POST /gateway/data-tool/tasks`
2. 平台转发请求到工具服务器
3. 工具服务器返回成功响应（状态码 201）
4. 平台从响应中提取 `task.id = task_abc123`
5. 在数据库中登记：`task_abc123` 属于当前用户
6. 返回响应给用户

#### 场景 3：列表过滤

**接口**：`GET /gateway/data-tool/files`

**业务含义**：查看文件列表，只返回当前用户的文件。

**资源规则配置**：

```
规则类型：列表过滤
列表路径：$.files
资源 ID 字段：file_id
资源类型：file
```

**上游响应示例**（未过滤）：
```json
{
  "files": [
    {"file_id": "f1", "name": "用户A的文件", "owner": "userA"},
    {"file_id": "f2", "name": "用户B的文件", "owner": "userB"},
    {"file_id": "f3", "name": "用户A的文件", "owner": "userA"}
  ]
}
```

**平台过滤后（假设当前用户是 userA）**：
```json
{
  "files": [
    {"file_id": "f1", "name": "用户A的文件", "owner": "userA"},
    {"file_id": "f3", "name": "用户A的文件", "owner": "userA"}
  ]
}
```

**执行逻辑**：
1. 用户调用 `GET /gateway/data-tool/files`
2. 平台转发请求到工具服务器
3. 工具服务器返回所有文件（未过滤）
4. 平台从 `$.files` 数组中读取每个文件的 `file_id`
5. 查询数据库：哪些 `file_id` 属于当前用户
6. 只保留属于当前用户的文件
7. 返回过滤后的响应

#### 场景 4：父子资源关系

**接口**：`POST /gateway/data-tool/tasks/{task_id}/results`

**业务含义**：为任务创建结果，结果应属于任务的所有者。

**资源规则配置**：

```
规则类型：路径参数提取 + 响应体登记

校验规则：
- 参数名：task_id
- 资源类型：task
- 校验时机：调用前

登记规则：
- JSONPath：$.result_id
- 资源类型：result
- 父资源：task_id
- 登记时机：调用成功后
```

**执行逻辑**：
1. 用户调用 `POST /gateway/data-tool/tasks/task_123/results`
2. 平台检查 `task_123` 是否属于当前用户
3. 如果不属于 → 返回 403
4. 如果属于 → 转发请求
5. 工具服务器返回 `{"result_id": "res_456"}`
6. 平台登记 `res_456` 属于当前用户，并关联到父资源 `task_123`
7. 返回响应

#### 场景 5：删除资源

**接口**：`DELETE /gateway/data-tool/datasets/{dataset_id}`

**业务含义**：删除数据集，只能删除自己的。

**资源规则配置**：

```
规则类型：路径参数提取
参数名：dataset_id
资源类型：dataset
校验时机：调用前
删除标记：是（调用成功后标记资源已删除）
```

**执行逻辑**：
1. 用户调用 `DELETE /gateway/data-tool/datasets/ds_123`
2. 平台检查 `ds_123` 是否属于当前用户
3. 如果不属于 → 返回 403
4. 如果属于 → 转发请求
5. 工具服务器删除成功，返回 204
6. 平台在数据库中标记 `ds_123` 已删除
7. 返回 204 给用户

> **提示**：标记删除后，该资源 ID 不会再通过归属校验。如果工具服务器复用 ID，平台会拒绝访问。

### 7.3 接口参数与限制配置

除了访问策略，还需要配置接口的技术参数。

**操作路径**：接口详情 → 执行策略

#### 7.3.1 请求限制

| 配置项 | 说明 | 推荐值 | 注意事项 |
| --- | --- | --- | --- |
| 允许的 Content-Type | 请求体的格式 | `application/json` | 根据接口实际需要设置 |
| 最大请求大小 | 请求体的字节数上限 | 10 MB | 文件上传接口可以设置更大 |
| 最大响应大小 | 响应体的字节数上限 | 50 MB | 文件下载接口可以设置更大 |
| 请求超时 | 等待上游响应的时间 | 30 秒 | 慢任务应使用异步模式 |

**Content-Type 配置**：

- `application/json`：JSON 格式请求体（最常用）
- `multipart/form-data`：文件上传
- `application/x-www-form-urlencoded`：表单提交
- `text/plain`：纯文本
- 多个值用逗号分隔：`application/json,text/plain`

#### 7.3.2 流式传输

| 配置项 | 说明 | 何时启用 |
| --- | --- | --- |
| 允许流式上传 | 支持分块上传大文件 | 文件上传接口 |
| 允许流式下载 | 支持分块下载大文件 | 文件下载接口 |

**启用流式传输的好处**：
- 不受请求/响应大小限制
- 降低内存占用
- 支持进度显示

**限制**：
- 流式传输时无法记录完整请求/响应体
- 无法对响应进行列表过滤（owner 策略的列表接口不支持流式）

#### 7.3.3 幂等性

| 配置项 | 说明 | 何时启用 |
| --- | --- | --- |
| 要求幂等键 | 客户端必须提供 `Idempotency-Key` 请求头 | 创建、支付、扣费等不可重复操作 |
| 幂等键有效期 | 相同幂等键的去重时间窗口 | 24 小时（默认） |

**幂等性说明**：

启用幂等键后，如果用户在短时间内使用相同的 `Idempotency-Key` 重复调用，平台会返回第一次调用的结果，而不会重复执行操作。

**适用场景**：
- 创建资源（避免重复创建）
- 扣费操作（避免重复扣费）
- 发送通知（避免重复发送）

**不适用场景**：
- 查询接口（可以重复调用）
- 更新接口（重复更新到相同值通常无害）

#### 7.3.4 限流配置

| 配置项 | 说明 | 推荐值 |
| --- | --- | --- |
| 单接口限流 | 该接口的每分钟调用上限 | 根据接口特点设置 |

**限流建议**：

| 接口类型 | 推荐限流 | 原因 |
| --- | --- | --- |
| 简单查询 | 60-120 次/分钟 | 负载低，可以较高 |
| 复杂计算 | 10-30 次/分钟 | 消耗资源多，需要限制 |
| 创建资源 | 30-60 次/分钟 | 防止滥用 |
| 文件上传 | 10-20 次/分钟 | IO 密集，需要限制 |
| 删除操作 | 10-30 次/分钟 | 敏感操作，严格控制 |

> **提示**：限流是多层的：用户级限流、工具级限流、接口级限流。最严格的限制会生效。

### 7.4 接口名称和文档优化

导入的接口名称和描述可能不够友好，可以优化后再发布。

**操作路径**：接口详情 → 对外展示

**可编辑内容**：

| 字段 | 说明 | 优化建议 |
| --- | --- | --- |
| 接口名称 | 用户看到的名称 | 使用业务术语，避免技术代号 |
| 接口说明 | 用途描述 | 详细说明能做什么、适用场景、限制 |
| Gateway 路径 | 对外路径 | 可以简化或重命名，但要保持语义 |
| 参数说明 | 每个参数的描述 | 说明参数含义、格式、是否必填 |
| 示例值 | 请求和响应示例 | 提供真实的示例数据 |

**优化示例**：

**优化前**：
- 名称：`getTasks`
- 说明：`Get tasks`
- 路径：`/gateway/data-tool/api/v1/task/list`

**优化后**：
- 名称：查看我的任务列表
- 说明：获取当前用户创建的所有数据分析任务，支持按状态和时间筛选。只返回属于当前用户的任务。
- 路径：`/gateway/data-tool/tasks`

> **重要**：优化后的内容会出现在用户的 API 文档中，必须准确、清晰、无内部术语。

## 8. 路由发布与验证

### 8.1 发布前检查

在发布路由前，必须确认所有准备工作已完成。

**检查清单**：

- [ ] 所有候选接口都已处理（放行/排除/阻断）
- [ ] 没有未决策的阻断级接口
- [ ] 放行的接口都已配置访问策略
- [ ] `owner` 策略的接口已配置完整资源规则
- [ ] 接口名称和说明已优化
- [ ] Gateway 路径没有冲突
- [ ] 限流、超时、大小限制已合理设置
- [ ] 工具连接测试通过
- [ ] 上游认证配置正确

**操作路径**：工具详情 → 发布管理 → 发布前校验

点击"执行发布前校验"按钮，平台会自动检查：

**校验项**：

| 校验内容 | 说明 | 不通过的后果 |
| --- | --- | --- |
| 接口决策完整性 | 所有接口都已明确处理 | 无法发布 |
| 阻断接口处理 | 阻断级接口已确认处理 | 无法发布 |
| 访问策略完整性 | 放行接口都有访问策略 | 无法发布 |
| 资源规则完整性 | `owner` 接口的资源规则已配置 | 无法发布 |
| Gateway 路径唯一性 | 没有路径冲突 | 无法发布 |
| 工具连接可达性 | 健康检查通过 | 警告，可以强制发布 |

**校验结果**：

- **全部通过**：显示绿色提示，可以继续发布
- **有错误**：显示红色错误列表，必须修复后才能发布
- **有警告**：显示黄色警告，可以选择修复或强制发布

### 8.2 发布操作

校验通过后，可以执行发布。

**操作路径**：工具详情 → 发布管理 → 发布路由

**发布方式选择**：

| 方式 | 说明 | 何时使用 |
| --- | --- | --- |
| 批量发布 | 一次性发布所有已放行接口 | 新工具首次上线 |
| 单接口发布 | 只发布选中的一个接口 | 增量上线或测试 |

#### 8.2.1 批量发布

**步骤 1：点击"批量发布"**

在发布管理页面，点击"批量发布"按钮。

**步骤 2：确认发布范围**

页面显示即将发布的接口列表，包含：
- 接口名称
- 方法和路径
- 访问策略
- 风险等级

检查列表，确认无误。

**步骤 3：填写审计原因**

必填字段，说明为什么要发布这些接口，例如：
- "新接入数据分析工具，首次上线全部业务接口"
- "需求变更，增加文件下载功能"
- "修复接口参数错误，重新发布"

**步骤 4：确认发布**

点击"确认发布"按钮。

**发布过程**：

1. 平台再次执行发布前校验
2. 为每个接口生成执行策略快照
3. 创建 Gateway 路由记录
4. 更新工具状态为"已启用"
5. 记录发布操作到审计日志

**发布结果**：

- **成功**：显示"发布成功，X 个接口已上线"
- **部分失败**：显示成功和失败的接口列表及原因
- **全部失败**：显示失败原因，不修改任何线上路由

> **重要**：批量发布是原子操作。如果有任何接口发布失败，整个批次都会回滚，不会部分发布。

#### 8.2.2 单接口发布

**步骤 1：进入接口详情**

找到要发布的接口，点击进入详情页面。

**步骤 2：检查配置**

确认访问策略、资源规则、限流等配置正确。

**步骤 3：点击"发布"**

页面顶部有"发布此接口"按钮。

**步骤 4：填写审计原因**

说明为什么要发布这个接口。

**步骤 5：二次确认**

如果接口是高风险的（例如删除操作），会弹出二次确认对话框，需要再次确认。

**步骤 6：确认发布**

点击"确认"按钮，接口发布成功。

### 8.3 发布后验证

发布成功后，必须验证接口是否真的可用。

**验证步骤**：

**步骤 1：确认工具已启用**

在工具列表中，确认工具状态为"已启用"（绿色标识）。

**步骤 2：用户侧查看文档**

使用普通用户账号登录：

1. 进入"工具与接口"页面
2. 找到刚发布的工具
3. 确认能看到已发布的接口
4. 检查接口名称、说明、路径是否正确
5. 确认看不到真实的上游地址和 Token

**步骤 3：创建测试 Key**

如果还没有测试用户的 Key：

1. 以测试用户身份登录
2. 进入"API 密钥"
3. 创建一个新 Key
4. 保存完整 Key

**步骤 4：执行测试调用**

选择一个低风险的查询接口进行测试。

**使用 curl 测试**：

```bash
curl -X GET "https://api.example.com/gateway/data-tool/health" \
  -H "X-API-Key: agw_your_test_key_here" \
  -v
```

**检查响应**：

- 状态码应该是 200（或接口预期的状态码）
- 响应内容符合预期
- 响应头中没有暴露上游服务器信息

**步骤 5：查看调用记录**

1. 以管理员身份登录
2. 进入"监控告警" → "调用记录"
3. 按 request_id 或测试用户搜索
4. 找到刚才的测试调用
5. 确认记录包含：
   - 正确的工具和接口
   - 状态码 200
   - 合理的耗时
   - request_id 可以复制

**步骤 6：测试错误场景**

测试几个失败场景，确认错误处理正确：

**测试 1：无 Key**
```bash
curl -X GET "https://api.example.com/gateway/data-tool/health"
```
预期：返回 401，错误码 `AUTHENTICATION_REQUIRED`

**测试 2：错误的 Key**
```bash
curl -X GET "https://api.example.com/gateway/data-tool/health" \
  -H "X-API-Key: invalid_key"
```
预期：返回 401，错误码 `INVALID_API_KEY`

**测试 3：未发布的路径**
```bash
curl -X GET "https://api.example.com/gateway/data-tool/nonexistent" \
  -H "X-API-Key: agw_your_test_key_here"
```
预期：返回 404，错误码 `ROUTE_NOT_FOUND`

**步骤 7：测试资源归属（如果有 owner 接口）**

如果发布了 `owner` 策略的接口，需要测试资源隔离是否正常：

1. 使用测试用户 A 创建一个资源（例如任务）
2. 记录资源 ID
3. 使用测试用户 B 尝试访问该资源
4. 预期：返回 403，错误码 `PERMISSION_DENIED`

**验收标准**：

- [ ] 用户文档中能看到接口
- [ ] 用户文档中看不到上游地址和 Token
- [ ] 测试调用返回正确结果
- [ ] 调用记录正确记录
- [ ] 无 Key 调用返回 401
- [ ] 错误 Key 返回 401
- [ ] 未发布路径返回 404
- [ ] 资源归属隔离正常（如适用）

### 8.4 发布后调整

发布后，如果需要修改接口配置：

**可以调整的**：
- 接口名称和说明
- 限流额度
- 超时时间
- 请求/响应大小限制

**需要重新发布的**：
- 访问策略变更
- 资源规则变更
- Gateway 路径变更
- 方法变更

**调整操作**：

1. 进入接口详情
2. 修改需要调整的配置
3. 如果是简单调整，点击"保存"即可生效
4. 如果需要重新发布，点击"重新发布"并填写原因

> **提示**：调整会立即生效，影响所有用户的调用。建议在低峰时段调整。
