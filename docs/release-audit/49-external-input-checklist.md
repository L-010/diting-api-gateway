# 外部输入清单

本清单按“必须提供才能解除上线阻断”和“建议提供”分组。每项都必须由指定责任方提供可复核输入；只给口头结论、截图无环境标识或只给本地演练结果，均不视为验证证据。

## 必须提供才能解除上线阻断

| 输入 | 需要谁提供 | 所需内容 | Codex 收到后执行 | 通过标准 | 不提供的上线影响 |
|---|---|---|---|---|---|
| 最终租户和管理员权限规则 | 产品负责人、安全负责人 | 三种策略选择、跨用户/跨租户规则、owner/shared/admin_only 精确定义、批准人和版本 | 更新权限决策包；补充真实模型/矩阵测试和负向测试 | 规则无歧义，矩阵全通过，审计和拒绝策略有证据 | BD-01 至 BD-03 P1 阻断，禁止上线 |
| 目标服务器或测试环境访问范围 | 基础设施负责人 | 环境标识、网络范围、受控账号、维护窗口、禁止访问范围、证据路径 | 运行目标预检、迁移前检查、健康/TLS/进程验证 | 仅访问批准范围，所有命令退出 0，敏感值不回显 | 生产迁移、TLS、回滚和 E2E 无法验证，P1 阻断 |
| 托管、反向代理和 TLS 方案 | 基础设施/网络负责人 | 进程管理器、worker/实例数、域名、证书链、TLS 最低版本、超时、限流、日志和重启策略 | 执行 `health_validate.py`、`tls_proxy_validate.py` 和重启演练 | HTTPS、证书、代理、readiness、重启和退出码均符合方案 | P1 部署/TLS/托管阻断 |
| 非生产 SMTP 凭证 | 邮件/基础设施负责人 | 沙箱主机、端口、TLS、最小账号、测试收件箱、过期时间和清理人 | 执行 SMTP 连通、成功、超时、认证、限流、幂等/重试和脱敏测试 | 六类场景通过，未触达生产收件人，日志脱敏 | SMTP P1 外部隔离阻断 |
| 非生产 TomoDD 凭证 | 集成负责人 | 沙箱根地址、白名单、最小 token、测试项目、限流/超时注入方式 | 执行健康、成功、认证失败、超时、限流、幂等和未知结果测试 | 资源归属正确，未知结果不重复副作用，凭证可撤销 | TomoDD P1 外部隔离阻断 |
| 非生产文件服务凭证 | 文件服务负责人 | 沙箱 endpoint、最小 token、测试前缀、manifest/下载/限流故障注入、清理方式 | 执行文件 manifest、下载、超时、认证、限流、幂等、脱敏和清理测试 | 元数据/正文/归属一致，越权和大文件边界拒绝 | 文件上游 P1 外部隔离阻断 |
| 预计日活、并发、数据量和性能 SLO | 业务负责人、基础设施、数据库负责人 | DAU、峰值并发、QPS、用户/资源/调用/文件规模、p95/p99、错误率、CPU/内存/连接门槛 | 生成参数，执行本地/测试压测和批准的只读生产探针 | 结果可重复且所有核心门槛通过，拓扑与目标一致 | SQLite/容量/性能 P1 阻断 |
| 备份频率、RPO、RTO | 业务、数据库、基础设施 | 数据库/文件/配置分别的频率、保留期、RPO、RTO、跨区策略、责任人 | 执行备份完整性、同引擎临时恢复、head/抽样和计时验证 | 恢复证据满足 RPO/RTO，抽样和权限一致 | 备份恢复 P1/P2 阻断 |
| 监控平台和告警接收方式 | 基础设施/值班负责人、安全负责人 | 指标/日志接入方式、仪表盘、P1/P2 接收组、确认时限、升级路径、维护窗口 | 按 45 号规范创建规则，注入合成告警并验证接收/确认/关闭 | 告警可到达、路由正确、关闭有恢复证据 | 监控告警闭环 P1/P2 阻断 |
| 发布窗口和回滚责任人 | 发布负责人、业务负责人 | 开始/结束时间、冻结范围、迁移负责人、应用制品负责人、数据库恢复负责人、业务验收人、通讯录 | 生成发布序列和回滚演练，检查值守覆盖 | 每一步有唯一责任人和替补，回滚制品/备份可用 | P1 发布治理阻断 |

## 建议提供

| 输入 | 需要谁提供 | Codex 收到后执行 | 不提供的影响 |
|---|---|---|---|
| 真实目标数据库引擎/版本和连接池门槛 | 数据库负责人 | 运行同引擎迁移、恢复和容量测试 | 只能保留临时 SQLite 证据，不能解除生产迁移/容量阻断 |
| 数据保留、删除、导出和合规期限 | 业务/法务/安全 | 补充到清理脚本、恢复和权限矩阵 | 数据治理与审计残余风险 |
| 失败注入开关或第三方沙箱控制台 | 各集成负责人 | 重复执行超时、限流、断连、未知结果场景 | 只能验证成功路径，外部副作用风险保留 |
| 浏览器版本、缓存路径和 CI 执行器 | 前端/基础设施 | 安装前检查并执行三种 E2E 模式 | 浏览器 E2E P2 阻断 |
| 告警阈值基线和维护窗口 | 值班/业务负责人 | 填充 45 号阈值、抑制和关闭状态机 | 不能证明告警业务闭环 |
| 运行制品哈希和上一版本 | 发布负责人 | 验证制品完整性和应用回滚路径 | 回滚只能停留在人工方案 |

## 输入接收格式

外部输入应通过受控工单或安全附件提供：环境标识、变量名称和状态、证据链接、批准人、有效期。不得发送密钥值、Cookie、完整 API Key、数据库连接串、签名 URL 或真实文件。Codex 收到后先做输入完整性检查，缺任何 P1 输入即停止，不以猜测补齐。
