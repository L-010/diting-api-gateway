# 第八阶段：Worker 至少一次处理结果

## 执行范围

- 使用项目 `.venv`、临时 SQLite、合成数据和本地 Mock/stub；未连接生产或真实第三方。
- 复用多进程领取测试，补充邮件 Outbox 的并发领取回归。

## 结果

| 场景 | 结果 | 分类 |
|---|---|---|
| Worker 领取后进程崩溃 | 非零退出后租约过期，另一进程可重新领取。 | 已验证通过；属于至少一次架构 |
| 租约到期重领、两个进程先后处理 | 条件更新保证同一时刻只有一个有效领取者。 | 已验证通过 |
| 文件同步/删除/验证重复执行 | 文件身份键、删除 404 成功和状态幂等路径保持结果等价。 | 已验证通过 |
| 外部副作用后状态提交失败 | 本地故障注入确认数据库无法回滚已发生的外部副作用；依赖端点去重或补偿。 | 仍是架构限制 |
| SMTP Outbox 两 Worker 并发发送 | 原实现可重复发送，已增加 `sending` 原子领取和过期恢复；回归测试通过。 | 已确认并修复 |
| SMTP 发送后进程崩溃/响应丢失 | SMTP 协议无法证明消息是否已接收，恢复重试可能重复发送。 | 无法在本地消除，必须明确为不保证幂等 |

## 回归

`.venv\Scripts\python.exe -m pytest backend\tests\test_phase7_local_risks.py -p no:cacheprovider -q`：`8 passed`；多进程 SQLite：`2 passed`。

## 边界

至少一次只描述任务领取和重试，不等同于外部副作用恰好一次，也不是生产容量证明。
