# 第七阶段：旧库用户名冲突迁移前处理结果

## 实现与执行

- `scripts/release_audit/migration_precheck.py` 新增只读扫描：使用 `NFKC + trim + casefold` 计算规范键，检测重复、空值、控制字符和规范化后超长值。
- 冲突报告只包含类型、数量、活跃/非活跃计数和规范键 SHA-256 摘要，不返回用户名、邮箱或用户 ID。
- `scripts/migrate.py` 在任何 Alembic 写入前调用该检查；冲突时非零退出。
- 新 migration `a3b4c5d6e7f8` 在写入 Unicode 规范键前再次检查，随后重建 `uq_users_username_key`；没有修改历史 migration。

## 结果

| 旧库数据 | 实际结果 | 分类 |
|---|---|---|
| 大小写、首尾空白冲突 | 预检查返回匿名冲突摘要；`scripts/migrate.py` 非零退出。 | 已确认并修复 |
| Unicode 合成/分解等价冲突 | 预检查发现同一规范键。 | 已确认并修复 |
| 已停用与现存用户冲突 | 报告保留活跃/非活跃数量，不自动选择保留方。 | 已验证通过 |
| 空用户名、控制字符、规范化超长 | 报告为非法用户名类别。 | 已验证通过 |
| 冲突迁移 | 不创建 `alembic_version`，原 users 行数不变。 | 已验证通过 |
| 解决冲突后的干净库 | 升级到 `a3b4c5d6e7f8`；插入 Unicode 等价用户名触发唯一约束。 | 已验证通过 |

## 处理选项

冲突报告不决定重命名、删除、合并或保留哪个用户。业务方必须根据用户归属、登录记录、关联资源和审计要求选择处理方式；处理完成后重新执行迁移前检查。

## 限制

直接绕过 `scripts/migrate.py` 执行历史 Alembic 命令不具备迁移前完整报告。发布流程必须使用该脚本或等价的预检查门禁；真实旧库升级仍需在经过授权的数据库副本中执行。
