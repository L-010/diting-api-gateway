# API Gateway 开发者平台 MVP 需求确认书

甲方确认版

## 一、文档目的

本文用于确认“API Gateway 开发者平台 MVP”的建设范围、主要功能、验收标准和不包含内容。甲乙双方确认后，本文作为后续开发、验收、交付和范围变更判断的依据。

如后续甲方提出本文未包含的新功能、流程调整、权限调整、数据迁移、生产运维或第三方系统对接需求，应按双方确认的变更流程另行评估工作量、周期和费用。

## 二、项目目标

本项目建设一个面向科研工具调用的 API 平台。平台的目标是让使用方无需直接接触真实后端服务地址和服务密钥，而是通过统一平台登录、统一 API Key 和统一调用入口使用已发布的科研工具接口。

平台首版重点解决以下问题：

1. 使用方注册后必须经过管理员审批，避免匿名或未授权使用。
2. 使用方只需要一个平台 API Key，即可调用已发布且允许使用的工具接口。
3. 管理员可以在后台接入科研工具、导入接口文档、审核哪些接口可以开放。
4. 平台记录每次调用的结果，便于排查失败、统计使用情况和追踪操作记录。
5. 普通用户看不到真实服务地址、服务 Token、内部接口和敏感配置。

## 三、用户角色

### 1. 公开访客

公开访客可以查看平台介绍、工具说明、接入流程，并提交注册申请。

### 2. 普通用户

普通用户指需要调用科研工具接口的使用方。普通用户在审批通过后可以登录平台、创建 API Key、查看工具接口文档，并在自己的程序中调用平台提供的统一接口。

### 3. 管理员

管理员负责用户审批、工具接入、接口审核、接口发布、调用监控、问题排查和审计查看。

## 四、首版交付范围

### 1. 公开访问页面

首版提供平台首页和工具说明页面，展示平台用途、调用方式、接入流程、安全边界、登录入口和注册申请入口。

首版真实接入工具为 tomoDD-SP。其他科研工具可作为后续扩展方向展示，但不承诺首版即可真实调用。

### 2. 注册、登录与审批

平台支持普通用户提交注册申请。注册申请提交后，账号默认不能登录，必须由管理员审批通过。

管理员可执行以下操作：

1. 查看待审批用户。
2. 审批通过用户。
3. 拒绝用户申请，并填写拒绝原因。
4. 停用已审批用户。
5. 重新启用已审批但被停用的用户。

被拒绝用户再次登录时，应看到申请被拒绝的提示。被停用用户不能继续登录，也不能继续使用已有 API Key 调用接口。

### 3. API Key 管理

普通用户审批通过并登录后，可以创建平台 API Key。API Key 用于调用平台统一接口。

API Key 管理规则如下：

1. 新建 API Key 后，完整密钥只显示一次。
2. 页面关闭或离开后，完整密钥不能再次查看。
3. 用户可以查看密钥前缀、创建时间、最后使用时间、状态和过期情况。
4. 用户可以主动禁用自己的 API Key。
5. 管理员只能看到密钥前缀和状态，不能查看完整密钥。
6. 管理员可以禁用存在风险或异常的 API Key。

### 4. 普通用户工作台

普通用户登录后可使用以下功能：

1. 使用概览：查看当前是否已有有效 API Key、可用工具数量、可用接口数量和最近调用情况。
2. 工具与接口：查看已发布且自己可用的工具和接口说明。
3. API 密钥：创建、查看和禁用自己的平台 API Key。
4. 调用记录：查看自己的接口调用记录和失败原因。

普通用户查看接口文档时，只能看到平台统一调用地址、请求方法、参数说明、请求示例、响应示例和错误说明。普通用户不能看到真实后端服务地址、后端 Token 或内部部署信息。

### 5. 管理员工作台

管理员登录后可使用以下功能：

1. 用户管理：审批用户、拒绝用户、停用用户、启用用户、批量导入普通用户。
2. 工具管理：新建工具、配置工具名称、说明、上游服务地址和认证方式。
3. 接口导入：通过 OpenAPI/Swagger 文档导入工具接口。
4. 接口审核：查看接口风险，决定接口放行、排除或阻断。
5. 路由发布：将审核通过的接口发布给用户调用。
6. 调用监控：查看调用量、成功率、错误率、耗时、流量、异常 Key 和失败请求。
7. 审计日志：查看用户审批、Key 管理、工具配置、接口发布等管理操作记录。

### 6. 工具接入

首版支持管理员接入科研工具服务。每个工具在首版中对应一个真实部署服务地址。

工具接入规则如下：

1. 工具需要配置名称、唯一标识、说明和上游服务地址。
2. 上游服务地址必须提前加入允许访问的白名单。
3. 工具可配置无认证、Bearer Token 或 Header API Key。
4. 上游 Token 由平台加密保存，不在页面回显。
5. 管理员可以执行连接测试，确认服务是否可达。
6. 首版不提供多个上游服务实例的切换、优先级、灰度和故障转移。

### 7. 接口导入与审核

平台支持通过 OpenAPI/Swagger 文档导入接口。导入后，接口不会自动开放给普通用户，必须由管理员审核。

平台会对接口进行基础风险识别，包括：

1. 内部接口。
2. 管理接口。
3. 调试接口。
4. 废弃接口。
5. 删除类接口。
6. 全局资源列表接口。
7. 可能涉及用户资源归属的接口。

管理员可对每个接口做以下决定：

1. 放行：允许进入发布候选。
2. 排除：不纳入本次发布。
3. 阻断：明确禁止发布。
4. 延后：暂不处理，后续再确认。

存在未确认的高风险或阻断接口时，平台不允许直接完成发布。

### 8. 接口发布

接口发布后，普通用户才能在工具文档中看到并调用。

发布规则如下：

1. 只有管理员确认放行的接口才能发布。
2. 发布前必须确认接口访问范围。
3. 发布前必须确认接口路径没有冲突。
4. 批量发布时，如存在未处理问题，则本次发布整体失败，不会部分发布。
5. 发布、停用、排除、阻断等操作都要写入审计日志。

### 9. 统一调用入口

普通用户的程序通过统一入口调用工具接口。调用时必须携带平台 API Key。

调用失败时，平台返回统一格式的错误信息，并附带 request_id。request_id 用于用户和管理员共同排查问题。

平台会拦截以下情况：

1. 未携带 API Key。
2. API Key 错误、禁用或过期。
3. 用户账号未审批、被拒绝或被停用。
4. 工具未启用。
5. 接口未发布。
6. 请求内容类型不允许。
7. 上传或下载内容超过限制。
8. 访问不属于自己的资源。
9. 上游服务不可达或超时。

### 10. 调用记录、监控与审计

平台记录每次接口调用的必要信息，包括 request_id、用户、工具、接口、状态码、错误码、耗时、请求流量、响应流量和时间。

平台不记录请求正文、不记录完整 API Key、不记录上游 Token、不记录密码。

普通用户只能查看自己的调用记录。管理员可以查看全平台调用监控，并按用户、工具、状态码、request_id 和时间范围筛选。

管理员可查看审计日志，包括用户审批、Key 禁用、工具创建、工具修改、接口导入、接口发布等操作。

## 五、首版不包含内容

以下内容不属于本次 MVP 首版交付范围，除非双方另行确认：

1. 匿名用户直接调用 API。
2. 普通用户在线调试接口作为主功能。
3. 普通用户查看真实后端服务地址、服务 Token 或内部部署信息。
4. 任意 URL 代理能力。
5. 多个上游服务实例、灰度发布、自动故障转移、手动切流。
6. 通过 CSV 创建管理员账号。
7. 自动发布导入的所有接口。
8. 默认开放删除类接口、内部接口、调试接口、全局资源列表接口。
9. 邮件、短信、企业微信、Webhook 等外部通知。
10. 调用记录或审计日志导出。
11. 生产级备份、恢复、密钥轮换和长期运维体系。
12. 除 tomoDD-SP 以外的其他科研工具真实业务联调。

## 六、验收标准

### 1. 用户侧验收

甲方可按以下标准验收普通用户功能：

1. 用户可以提交注册申请。
2. 未审批用户不能登录。
3. 管理员审批通过后，用户可以登录。
4. 用户可以创建 API Key，完整密钥只显示一次。
5. 用户可以查看已发布工具和接口文档。
6. 用户接口文档中不出现真实后端服务地址和 Token。
7. 用户可以复制调用示例并按示例调用已发布接口。
8. 调用成功或失败后，用户可以在调用记录中看到对应记录。
9. 调用失败时，用户可以获得 request_id。
10. 用户不能查看其他用户的调用记录。

### 2. 管理侧验收

甲方可按以下标准验收管理员功能：

1. 管理员可以审批、拒绝、停用和启用普通用户。
2. 管理员拒绝用户时可以填写拒绝原因。
3. 管理员可以批量导入普通用户，且不能通过导入创建管理员。
4. 管理员可以查看用户 API Key 前缀和状态。
5. 管理员可以禁用问题 API Key。
6. 管理员可以新建工具并配置上游服务。
7. 管理员可以执行工具连接测试。
8. 管理员可以导入 OpenAPI/Swagger 接口文档。
9. 管理员可以查看接口风险并做放行、排除或阻断决策。
10. 未完成风险处理或访问范围确认时，平台不允许发布接口。
11. 管理员可以发布已确认接口。
12. 发布后普通用户可以在文档中看到对应接口。
13. 管理员可以查看调用监控、失败请求和审计日志。
14. 管理员可以通过 request_id 定位一次调用或一次操作。

### 3. 安全与边界验收

甲方可按以下标准验收安全边界：

1. 普通用户页面不展示真实上游 Token。
2. 普通用户页面不展示完整上游部署信息。
3. 完整 API Key 创建后只显示一次。
4. 管理员也不能查看用户完整 API Key。
5. 被禁用或过期的 API Key 无法继续调用接口。
6. 被停用用户无法继续登录或调用接口。
7. 未发布接口无法调用。
8. 平台不保存请求正文、密码、完整 API Key 或上游 Token。

请甲方重点确认以下事项：

1. 是否确认本项目首版定位为“开发者 API Gateway 平台”？
2. 是否确认首版真实接入工具仅为 tomoDD-SP？
3. 是否确认普通用户必须经过管理员审批后才能使用？

5. 是否允许用户同时保留多个有效 API Key？
6. 是否保留 CSV 批量导入普通用户功能？
7. 是否确认每个工具首版只配置一个上游服务地址？
8. 是否确认导入接口后必须人工审核，不能自动全部开放？
9. 是否确认删除类、内部类、调试类、全局列表类接口默认不开放？
10. 是否确认普通用户不能看到真实服务地址和服务 Token？
11. 是否确认首版不包含邮件、短信、企业微信、Webhook 等通知？
12. 是否确认首版不包含调用记录导出和审计日志导出？
13. 是否确认首版不包含生产级备份恢复和长期运维体系？

## 八、变更约定

本文确认后，以下情况视为需求变更，应另行评估：

1. 新增本文未列明的功能。
2. 调整用户审批、权限、安全边界或发布规则。
3. 新增其他科研工具真实业务联调。
4. 接入第三方通知、支付、组织架构、统一身份认证等外部系统。
5. 从本地 MVP 升级为生产级高可用部署。
6. 要求导出、统计报表、长期日志留存或监管报表。
7. 要求多环境、多实例、灰度、熔断、自动故障转移。
