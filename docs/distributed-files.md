# 分布式工具文件与制品

## 运行模型

文件正文只保存在工具服务器。平台数据库只保存平台文件 ID、所有者、工具、不可见的上游文件 ID、状态、大小、校验值、保留期和资源关联。门户下载必须先创建五分钟授权，再由平台鉴权并流式代理；平台不返回上游地址、真实路径或凭据。

生产环境中，只要任一工具配置了任务或制品能力，就必须持续运行文件同步进程：

```powershell
powershell -ExecutionPolicy Bypass -File .\scripts\run-file-worker.ps1
```

SQLite 仅运行一个文件同步进程。生产数据库可以运行多个进程，数据库租约会避免同一资源被同时处理。未配置制品能力时不启动该进程也不影响 Gateway 和门户启动。

## 新工具契约

1. 工具返回稳定、不透明的 `file_id`，不能返回绝对路径或任意下载 URL。
2. Manifest 遵循 [remote-file-manifest-v1.schema.json](./schemas/remote-file-manifest-v1.schema.json)，单次不超过 1 MiB 和 1000 项。
3. `ready` 文件必须提供 `size_bytes`；不能提供时先上报 `pending`，由单文件下载能力的 HEAD 响应补齐。上游不支持 HEAD 时，平台只会回退为 `Range: bytes=0-0` 探测，不会把正文载入内存。
4. 文件名只用于展示，平台会移除目录、换行和控制字符。文件访问端点必须将平台传入的 URL 编码 ID 当作不透明标识处理。
5. 工具应提供状态、Manifest、单文件下载、删除和存储水位接口；仅支持 ZIP 的旧工具可以只配置整包下载。

适配器示例位于 [tool-file-adapter-v2.example.json](./tool-file-adapter-v2.example.json)。本地校验：

```powershell
.\.venv\Scripts\python.exe .\scripts\validate_file_manifest.py .\manifest.json
```

## 生命周期边界

- 工具停用只阻止新调用，不自动阻止历史下载；文件访问开关和安全隔离独立控制。
- 工具迁移服务器后，历史任务和文件继续绑定创建时的存储端点版本及冻结适配器。旧端点仍有关联任务、文件或待删除项时不得移除。
- 用户配额耗尽后允许下载、删除和运行中任务完成，只拒绝新上传及新产文件任务。
- 上游 `404` 只在下载时将文件标记为缺失，在删除时按幂等成功处理；网络错误不会误删元信息。
- 物理删除后保留 90 天墓碑，之后清除文件名、MIME 和校验值等敏感元信息。
- 终态任务和可下载文件按 `FILE_VERIFY_INTERVAL_SECONDS` 周期复核；用户是否打开页面不影响后台同步。
- 存储水位超过 `STORAGE_WATERMARK_MAX_AGE_SECONDS` 未更新时视为过期，平台拒绝新的产文件写入，避免依据旧容量误放行。
- 下载并发使用数据库唯一槽位和短租约实现。客户端断开、上游断流和超限都会结束事件并释放槽位；进程异常遗留的槽位会在租约到期后回收。

## 下载边界

- 单文件和整包制品都必须先成为平台 `RemoteFile`，再通过带 CSRF 的 POST 创建五分钟授权；旧任务直链返回 `410`，不会绕过审计与并发限制。
- 平台在发送响应头前校验已知 `Content-Length` 或 `Content-Range`。未知长度流在超过硬上限时立即中断，并记录失败事件，绝不伪造成功。
- 管理员可在“任务与文件 -> 下载访问记录”查询所有传输事件；管理员下载的授权、完成、失败和中断同时进入审计日志。
