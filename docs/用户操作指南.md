# 用户操作指南

## 1. 你可以用平台做什么

平台为多个独立部署的工具提供统一 API 入口。你只需要申请平台账号、创建一把平台 API Key，并按照工具文档中的 Gateway 地址调用服务。

你不需要知道工具部署在哪台服务器，也不能直接访问工具服务器。平台会在后台完成鉴权、限流、权限校验和安全转发。

## 2. 首次使用流程

### 第一步：注册并完成邮箱验证

在公开首页选择注册，提交账号信息后完成邮箱验证。验证成功不等于已经取得调用权限，还需要等待管理员审批。

如果平台尚未配置邮件服务，公开注册、邮箱验证和自助找回密码会关闭。此时请联系管理员通过受控方式为你开通账号。

### 第二步：等待审批并登录

管理员批准后，你才能登录、查看工具、创建 Key 和调用 Gateway。

以下状态会阻止使用：

| 状态 | 说明 | 该怎么做 |
| --- | --- | --- |
| 待审批 | 管理员尚未批准申请 | 等待处理或联系管理员确认申请信息 |
| 已拒绝 | 管理员没有批准申请 | 按页面提示或联系管理员了解处理方式 |
| 已停用 | 管理员暂停了账号使用资格 | 联系管理员处理，不要继续使用旧 Key |
| 必须修改密码 | 管理员导入了临时账号 | 登录后先完成改密，再进入门户 |

### 第三步：查看门户概览和快速接入信息

登录后，门户会显示你是否已有有效 Key、是否已有可调用工具，以及近期调用概况。

在“快速接入”或“工具与接口”中确认以下信息：

- 统一 Gateway Base URL：你的程序请求要使用的平台入口。
- API Key 请求头：当前使用 `X-API-Key`。
- 工具 Gateway 前缀和具体接口路径。
- 可复制的 curl、Python 或 JavaScript 示例。
- 标准错误码和 request_id 排障方式。

不要自行把 Gateway 地址替换为工具服务地址。工具的真实服务器地址不属于用户调用契约。

## 3. 创建并安全使用 API Key

进入“API 密钥”，填写一个便于识别的标签，例如“生产 Python 服务”或“测试环境集成”，再选择有效期。

创建成功后，完整 Key 只显示一次，并会在页面中短暂保留。请立即复制并安全保存；关闭页面后无法找回完整值。

### Key 应保存在哪里

建议保存到：

- 你自己后端服务的环境变量。
- 团队使用的密钥管理系统。
- 受控的部署平台密钥配置。

不要保存到：

- 浏览器前端代码。
- Git 仓库、提交记录或示例文档。
- URL 查询参数。
- 普通日志、截图、聊天记录或公开工单。

### Key 的状态

| 状态 | 含义 | 你的操作 |
| --- | --- | --- |
| 可用 | 可以调用已发布且启用的工具接口 | 正常使用，留意到期时间 |
| 已过期 | 超过创建时选择的有效期 | 创建新 Key 并更新程序 |
| 已禁用 | 你或管理员已停止该 Key | 不要继续重试，改用新 Key 或联系管理员 |
| 长期有效 | 没有自动到期时间 | 仍应定期轮换 |

如果需要更换 Key、Key 即将到期或怀疑泄露，请按以下顺序操作：先创建新 Key，再更新你的程序并验证调用成功，最后禁用旧 Key。不要先禁用旧 Key，以免生产程序中断。

## 4. 查找工具和接口

进入“工具与接口”。这里仅展示管理员已经发布、工具处于启用状态且对你开放的工具。

每张工具卡会显示：

| 内容 | 含义 |
| --- | --- |
| 工具名称和说明 | 工具提供什么能力、适合什么用途 |
| 工具 slug | Gateway 路径中的工具短名称 |
| 可用接口 | 当前可调用的接口数量 |
| 请求方法 | GET、POST、PUT、PATCH、DELETE 或 HEAD |
| 资源隔离 | 是否存在只能访问自己资源的接口 |
| Gateway 前缀 | 该工具所有对外接口的共同路径开头 |

选择工具后，你可以查看每个接口的用途、参数、请求体、响应示例、访问范围、大小限制、超时、重试要求和标准错误码。

页面展示的是 Gateway 路径，不是上游路径。请以页面中的 Gateway 地址和示例为准。

## 5. 在程序中调用接口

一次调用由四部分组成：请求方法、统一 Gateway 地址、工具接口路径和 `X-API-Key` 请求头。

示意结构如下，其中方括号内的内容需要替换：

```text
[请求方法] [Gateway Base URL]/gateway/[工具 slug]/[接口路径]
X-API-Key: [你的完整 API Key]
```

例如，页面提供的 curl、Python 和 JavaScript 示例已经包含正确的路径结构。复制后只替换完整 Key、路径参数、查询参数和请求体中的示例值。

调用前请确认：

1. 使用的是有效的完整 Key，而不是 Key 前缀。
2. 请求方法与文档一致。
3. URL 使用 Gateway 地址和 Gateway 路径。
4. `Content-Type`、请求体和文件大小符合文档要求。
5. 需要路径参数或查询参数时，已经替换成真实值。
6. 对可能重复执行的写操作，按文档要求提供 `Idempotency-Key`。

## 6. 资源、任务、文件与制品

部分工具会创建任务、结果文件或制品。是否有这些能力取决于管理员是否为该工具配置并发布了对应接口，因此不是每个工具都一定显示任务或文件内容。

### 访问自己的资源

带有“创建者资源”或 `owner` 访问范围的接口，只允许访问你自己创建的任务、文件、数据集或结果。不要尝试通过修改 URL 中的 ID 访问其他人的资源，平台会进行归属校验并拒绝不属于你的请求。

### 查看任务

“任务中心”会显示平台已登记且属于你的任务。可用能力由工具配置决定，可能包括状态、日志、清单、制品列表或下载。页面没有显示某项能力时，通常表示该工具尚未配置或发布该能力。

### 查看和下载文件

“文件与制品”只展示你的相关文件。只有状态为“可下载”的文件才可以下载。

| 文件状态 | 含义 | 你的操作 |
| --- | --- | --- |
| 可下载 | 文件已准备完成 | 可以下载或按需要删除 |
| 同步中 | 平台正在同步或确认文件信息 | 等待后刷新 |
| 删除中 | 删除请求已进入处理 | 等待完成，不要重复发起 |
| 已过期 | 超出保留期限 | 联系管理员确认是否可恢复或重新生成 |
| 上游已清理 | 工具服务已不再保留文件 | 通常需要重新执行任务 |
| 异常 | 文件同步或访问发生问题 | 记录文件信息和 request_id 联系管理员 |

## 7. 查看调用记录并排障

进入“调用记录”可以查看你通过 Gateway 发起的请求。记录中包含时间、工具与接口、状态码、错误码、耗时、请求/响应流量和 request_id。

当调用失败时，优先保存 request_id。它是管理员定位同一次请求最有效的信息。你可以按 request_id、工具 slug、状态码、方法、Key 和时间范围筛选，也可以导出 CSV 留存分析。

### 常见错误

| 现象 | 常见原因 | 你可以先做什么 |
| --- | --- | --- |
| 401 | 缺少 Key、Key 无效、已过期、已禁用或账号不可用 | 检查 `X-API-Key`、Key 状态和账号状态 |
| 403 | 没有工具权限，或资源不属于你 | 检查接口访问范围、资源 ID 和账号权限 |
| 404 | 路径或方法不正确，接口未发布 | 从工具文档重新复制 Gateway 路径和方法 |
| 413 | 请求或响应超过限制 | 缩小文件或数据量，按接口说明拆分请求 |
| 415 | Content-Type 不符合要求 | 检查请求头和提交数据格式 |
| 429 | 超过限流额度 | 降低并发、增加退避重试，必要时联系管理员评估额度 |
| 502 | 工具服务不可达或返回异常 | 保存 request_id，联系管理员排查工具服务 |
| 503 | 工具已停用或暂不可用 | 查看通知或联系管理员确认维护安排 |
| 504 | 工具服务处理超时 | 保存 request_id；不要对写操作无条件重复提交 |

### 联系管理员时应提供什么

- request_id。
- 调用时间和时区。
- 工具名称或 slug。
- 使用的方法和 Gateway 路径，不要提供完整 Key。
- 状态码和错误码。
- 是否能稳定复现，以及最近是否更新过程序、Key 或请求参数。

不要在工单、邮件或聊天中发送完整 API Key、密码或敏感请求正文。

## 8. 通知与账户安全

### 通知

“通知”会展示审批结果、Key 临期、密码和账户安全变化等信息。收到 Key 临期通知后，应尽早创建新 Key 并完成轮换。

### 账户设置

在“账户设置”中可以维护显示名称、密码和邮箱。更换邮箱需要邮件服务已配置，并完成新邮箱验证。修改密码后，应检查运行环境中的 Key 与账号状态是否仍符合团队的安全管理要求。

## 9. 重要使用边界

- 平台当前使用一把全局 Key 调用全部已发布且启用的工具接口；请按环境和用途使用清晰的 Key 标签。
- 你的 Key 只能用于你的程序，不应在浏览器页面或第三方客户端中暴露。
- 平台不允许你看到或直接使用工具的真实服务器地址和上游凭证。
- 你只能查看自己的调用记录、任务、文件和创建者资源。
- 某项任务或文件功能未出现，不代表账号异常，可能是工具本身没有配置该能力。
- Gateway 的错误响应会包含可用于排障的 request_id；保存它比反复重试更有帮助。
