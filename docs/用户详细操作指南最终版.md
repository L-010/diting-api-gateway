## 1. 平台简介

### 1.1 平台是什么

这是一个 API Gateway 开发者平台（API 网关开发者平台），为您提供统一的 API 调用入口。平台将多个独立部署的专业工具服务集中管理，您只需要：

1. 申请一个平台账号
2. 创建一把 API Key（API 密钥）
3. 在您的程序中通过统一地址调用服务

您不需要知道这些工具部署在哪台服务器，也不需要分别向每个工具申请权限。平台会在后台完成身份验证、权限校验、调用转发和安全保护。

### 1.2 平台能做什么

- **统一调用入口**：一把 Key 调用所有已开放的工具接口
- **自动鉴权**：平台自动验证您的身份和权限
- **资源隔离**：您只能访问自己创建的任务、文件和数据
- **调用记录**：完整保留调用历史，方便排查问题
- **安全保护**：限流、超时、错误处理等保护机制

### 1.3 基本概念（3分钟读懂）

**API（应用程序接口）**：程序之间互相调用的方式。您的程序通过 API 向平台发送请求，平台处理后返回结果。

**Gateway（网关）**：平台的统一入口。所有请求都先到达 Gateway，由它验证身份、检查权限，再转发到真实的工具服务。

**API Key（API 密钥）**：证明您身份的凭证，类似于密码。您的程序在调用时需要携带这个 Key，平台才知道是谁在调用。

**工具（Tool）**：平台接入的一个专业服务，例如某个数据处理工具、计算服务或查询系统。每个工具提供若干个接口。

**接口（Endpoint）**：工具提供的一项具体能力，例如"查询数据"、"创建任务"、"下载文件"等。

**request_id（请求编号）**：每次调用的唯一编号。当调用出现问题时，您可以把这个编号提供给管理员，帮助快速定位问题。

## 2. 术语表

### 2.1 账号相关

| 术语 | 解释 | 示例或说明 |
| --- | --- | --- |
| 平台账号 | 您在平台注册的用户身份 | 用于登录平台门户，查看文档和调用记录 |
| 邮箱验证 | 注册时需要点击邮件中的链接确认 | 证明您提供的邮箱是真实有效的 |
| 待审批 | 管理员尚未批准您的注册申请 | 此时还不能登录和调用接口 |
| 已审批 | 管理员已批准，可以正常使用 | 可以登录、创建 Key、调用接口 |
| 已停用 | 账号被管理员暂停使用 | 已有的 Key 会失效，无法继续调用 |
| 临时密码 | 管理员创建账号时的初始密码 | 首次登录后必须修改 |

### 2.2 API 密钥相关

| 术语 | 解释 | 示例或说明 |
| --- | --- | --- |
| API Key | 程序调用时使用的凭证 | 以 `agw_` 开头的长字符串 |
| Key 前缀 | Key 的前几个字符，用于识别 | 例如 `agw_1a2b3c`，不能用于调用 |
| 完整 Key | 创建时显示的完整字符串 | 只显示一次，必须立即保存 |
| 有效期 | Key 可以使用的时间长度 | 30/90/180/365 天或永久 |
| 已过期 | 超过有效期，不能继续使用 | 需要创建新 Key 替换 |
| 已禁用 | 您或管理员手动停用的 Key | 不能继续使用，需要用新 Key 替换 |
| Key 轮换 | 定期更换 Key 的安全操作 | 先创建新 Key，切换程序，再禁用旧 Key |

### 2.3 调用相关

| 术语 | 解释 | 示例或说明 |
| --- | --- | --- |
| Gateway 地址 | 平台统一的调用入口 | 例如 `https://api.example.com` |
| 工具 slug | 工具的唯一短名称 | 由小写字母、数字和短横线组成 |
| Gateway 路径 | 完整的接口调用地址 | `/gateway/{工具slug}/{接口路径}` |
| 请求方法 | 调用接口的操作类型 | GET（查询）、POST（创建）、PUT/PATCH（更新）、DELETE（删除） |
| X-API-Key | 请求头中携带 Key 的字段名 | 您的程序需要在这个位置放入完整 Key |
| request_id | 每次调用的唯一编号 | 用于排障，失败时务必保存 |
| 状态码 | 调用结果的编号 | 200 成功，400 请求错误，401 未授权，403 无权限，429 超限，500 服务错误 |

### 2.4 资源相关

| 术语 | 解释 | 示例或说明 |
| --- | --- | --- |
| 资源 | 任务、文件、数据集等数据对象 | 通过调用接口创建或获取 |
| 创建者资源 | 只有创建者能访问的资源 | 您不能访问其他用户的任务或文件 |
| 资源归属 | 判断资源是否属于您 | 平台会自动校验，拒绝访问他人资源 |
| 任务 | 工具异步处理的工作项 | 例如数据分析任务、计算任务 |
| 文件 | 任务产生的输入、输出或日志 | 状态为"可下载"时才能下载 |
| 制品 | 任务的最终结果文件 | 例如分析报告、处理结果 |

## 3. 快速上手

本节带您完成从注册到第一次成功调用的完整流程，预计 15 分钟。

### 3.1 注册账号

**步骤 1：访问平台首页**

打开浏览器，访问平台地址（由管理员提供），点击页面右上角的"注册"按钮。

**步骤 2：填写注册信息**

- **用户名**：您的登录名称，不能包含空格或特殊字符
- **密码**：至少 12 个字符，建议包含大小写字母、数字和符号
- **邮箱**：真实有效的邮箱地址，用于接收验证邮件
- **显示名称**（可选）：在平台中显示的名字
- **申请说明**：简要说明您的使用目的，帮助管理员审批

**步骤 3：验证邮箱**

提交注册后，您会收到一封验证邮件。点击邮件中的链接完成验证。

> **注意**：如果没有收到邮件，请检查垃圾邮件箱。如果平台未配置邮件服务，注册功能会关闭，此时请联系管理员为您开通账号。

**步骤 4：等待审批**

验证邮箱后，您的申请进入"待审批"状态。管理员会核对您的申请信息，通常在 1-2 个工作日内完成审批。

审批通过后，您会收到通知邮件（如果配置了邮件服务），或者您可以尝试登录查看状态。

### 3.2 首次登录

**步骤 1：进入登录页面**

访问平台首页，点击"登录"按钮。

**步骤 2：输入用户名和密码**

输入注册时使用的用户名和密码，点击"登录"。

**步骤 3：修改临时密码（如适用）**

如果您的账号是管理员创建的，首次登录时会要求修改临时密码。按照提示输入当前密码和新密码完成修改。

**步骤 4：查看使用概览**

登录成功后，您会进入"使用概览"页面。这个页面显示：

- **接入状态**：是否已有 API Key、是否有可用工具
- **运行指标**：调用量、成功率、延迟、总流量
- **需要关注**：临期 Key、运行中任务
- **可用工具**：平台已开放的工具列表

如果"接入状态"显示"尚无有效 Key"，说明您还没有创建 API Key，这是下一步要做的。

### 3.3 创建第一个 API Key

**步骤 1：进入 API 密钥页面**

在左侧菜单中点击"API 密钥"，或者在"使用概览"页面的"接入状态"区域点击"API 密钥"卡片。

**步骤 2：点击"创建新 Key"**

在页面右上角找到"创建新 Key"按钮并点击。

**步骤 3：填写 Key 信息**

- **标签**：为这个 Key 起一个便于识别的名字，例如"生产环境 Python 服务"、"测试环境"
- **有效期**：选择 Key 的有效时间
  - 30 天：适合临时测试
  - 90 天（推荐）：常规使用
  - 180 天 / 365 天：长期项目
  - 永久：需要特别确认风险，不推荐

**步骤 4：立即保存完整 Key**

点击"创建"后，页面会显示完整的 Key（以 `agw_` 开头的长字符串）。**这是唯一一次看到完整 Key 的机会**，请立即复制并保存到安全的地方：

- ✅ 保存到后端服务的环境变量
- ✅ 保存到团队的密钥管理系统
- ✅ 保存到受控的配置文件（不要提交到 Git）
- ❌ 不要保存到浏览器前端代码
- ❌ 不要提交到 Git 仓库
- ❌ 不要放在聊天记录或截图中

> **重要**：关闭页面后无法找回完整 Key。如果丢失，只能创建新 Key 替换。

### 3.4 查找可用的工具和接口

**步骤 1：进入工具与接口页面**

在左侧菜单中点击"工具与接口"。

**步骤 2：浏览工具列表**

页面会显示所有已开放的工具。每个工具卡片包含：

- **工具名称**：例如"数据分析工具"
- **工具说明**：简要介绍工具的用途
- **工具 slug**：短名称，例如 `data-tool`
- **接口数量**：该工具有多少个可用接口
- **Gateway 前缀**：调用时的路径前缀，例如 `/gateway/data-tool`

**步骤 3：查看接口详情**

点击工具卡片，进入该工具的接口列表。每个接口显示：

- **接口名称和用途**
- **请求方法**：GET、POST、PUT、DELETE 等
- **Gateway 路径**：完整的调用地址
- **参数说明**：需要传入什么数据
- **请求示例**：curl、Python、JavaScript 示例代码
- **响应示例**：成功时返回的数据格式
- **错误说明**：可能的错误情况

### 3.5 第一次调用

假设您要调用一个简单的查询接口，以下是完整步骤。

**步骤 1：从接口文档复制示例**

在接口详情页面，找到"请求示例"区域，复制 curl 或您熟悉语言的示例代码。

**curl 示例**：
```bash
curl -X GET "https://api.example.com/gateway/data-tool/query?id=123" \
  -H "X-API-Key: agw_your_actual_key_here"
```

**Python 示例**：
```python
import requests

response = requests.get(
    "https://api.example.com/gateway/data-tool/query",
    params={"id": "123"},
    headers={"X-API-Key": "agw_your_actual_key_here"}
)
print(response.json())
```

**JavaScript 示例**：
```javascript
fetch("https://api.example.com/gateway/data-tool/query?id=123", {
  headers: {
    "X-API-Key": "agw_your_actual_key_here"
  }
})
  .then(response => response.json())
  .then(data => console.log(data));
```

**步骤 2：替换占位符**

- 将 `https://api.example.com` 替换为实际的 Gateway 地址（在文档页面顶部显示）
- 将 `agw_your_actual_key_here` 替换为您刚创建的完整 Key
- 将 `id=123` 等参数替换为真实的查询值

**步骤 3：执行调用**

在您的终端或程序中执行上述代码。

**步骤 4：查看结果**

- **成功**：返回 JSON 格式的数据，状态码 200
- **失败**：返回错误信息，包含 `code`（错误码）、`message`（错误描述）、`request_id`（请求编号）

### 3.6 查看调用记录

**步骤 1：进入调用记录页面**

在左侧菜单中点击"调用记录"。

**步骤 2：找到刚才的调用**

页面显示您的所有调用记录，最新的在最上方。找到刚才的调用，查看：

- **request_id**：这次调用的唯一编号
- **工具和接口**：您调用的是哪个工具的哪个接口
- **状态码**：200 表示成功，400+ 表示错误
- **耗时**：这次调用花了多少毫秒
- **时间**：调用的准确时间

如果调用失败，点击该记录查看详细的错误信息和 request_id。

**恭喜！您已经完成第一次调用。**

接下来可以：
- 阅读更多工具的接口文档
- 在您的项目中集成 API 调用
- 学习如何处理错误和超时
- 了解资源归属和任务管理

## 4. 账号管理

### 4.1 账号状态说明

您的账号可能处于以下状态之一：

| 状态 | 说明 | 您能做什么 | 不能做什么 |
| --- | --- | --- | --- |
| 待审批 | 已完成邮箱验证，等待管理员批准 | 查看公开页面 | 登录、创建 Key、调用接口 |
| 已审批 | 管理员已批准，账号正常 | 登录、创建 Key、调用接口、查看记录 | - |
| 已停用 | 管理员暂停了账号 | 查看停用原因 | 登录、使用已有 Key |
| 已拒绝 | 管理员未批准申请 | 查看拒绝原因，联系管理员 | 登录、使用平台 |
| 必须修改密码 | 管理员创建的账号，使用临时密码 | 登录并修改密码 | 修改密码前不能使用门户 |

**查看账号状态**：

1. 尝试登录平台
2. 如果无法登录，页面会显示具体原因（待审批、已停用、已拒绝）
3. 如果能登录但要求改密码，说明您使用的是临时密码

### 4.2 修改密码

**适用场景**：
- 定期更换密码（建议每 90 天）
- 怀疑密码泄露
- 管理员要求修改
- 首次登录临时密码账号

**操作步骤**：

1. 登录后，点击右上角用户名，选择"账户设置"
2. 在"账户设置"页面找到"修改密码"区域
3. 填写：
   - **当前密码**：您现在使用的密码
   - **新密码**：至少 12 个字符，建议包含大小写字母、数字和符号
   - **确认新密码**：再次输入新密码
4. 点击"保存修改"

**密码要求**：
- 至少 12 个字符
- 不能与用户名相同
- 建议包含大小写字母、数字和符号
- 不要使用常见密码（如 `password123`）

**修改密码后**：
- 当前浏览器会话不会断开，您可以继续使用
- 下次登录时使用新密码
- 已创建的 API Key 不受影响，不需要更换

### 4.3 更换邮箱

**前提条件**：平台已配置邮件服务（如果未配置，此功能不可用）

**操作步骤**：

1. 进入"账户设置"页面
2. 找到"邮箱地址"区域，点击"更换"
3. 输入新的邮箱地址
4. 点击"发送验证邮件"
5. 打开新邮箱，点击验证邮件中的链接
6. 验证成功后，新邮箱生效

**注意事项**：
- 更换邮箱需要验证新邮箱
- 验证完成前，旧邮箱仍然有效
- 更换邮箱不会影响已有的 API Key 和调用权限

### 4.4 修改显示名称

显示名称是在平台中显示的名字，不是登录用户名。

**操作步骤**：

1. 进入"账户设置"页面
2. 找到"显示名称"字段
3. 输入新的显示名称（可选，留空则显示用户名）
4. 点击"保存修改"

### 4.5 账号安全最佳实践

**密码安全**：
- 使用强密码，至少 12 个字符
- 不要在多个网站使用相同密码
- 定期更换密码（建议每 90 天）
- 不要把密码告诉他人或写在纸上

**API Key 安全**：
- 只在后端服务中使用 Key，不要放在前端代码
- 不要把 Key 提交到 Git 仓库
- 不要在聊天、邮件、工单中发送完整 Key
- 定期轮换 Key（见第 5.5 节）
- 如果怀疑泄露，立即禁用旧 Key 并创建新 Key

**账号监控**：
- 定期查看"调用记录"，确认没有异常调用
- 查看"API 密钥"页面的"最后使用时间"，确认是您的程序在使用
- 如果发现异常，立即禁用所有 Key 并联系管理员

## 5. API 密钥

### 5.1 什么是 API Key

API Key（API 密钥）是您的程序调用平台接口时使用的凭证，类似于密码，但有以下区别：

| 对比项 | 密码 | API Key |
| --- | --- | --- |
| 用途 | 登录平台门户 | 程序调用接口 |
| 使用位置 | 浏览器登录页面 | 程序代码中的请求头 |
| 可以有几个 | 1 个 | 可以创建多个 |
| 有效期 | 永久（除非修改） | 可以设置过期时间 |
| 泄露后 | 修改密码 | 禁用该 Key，用新 Key 替换 |
| 格式 | 任意字符 | 以 `agw_` 开头的固定格式 |

### 5.2 创建 API Key

**操作步骤**：

1. 在左侧菜单点击"API 密钥"
2. 点击页面右上角的"创建新 Key"按钮
3. 填写信息：
   - **标签**：便于识别的名称，例如：
     - "生产环境 Python 服务"
     - "测试环境集成"
     - "数据分析脚本"
   - **有效期**：选择 Key 的使用期限
     - **30 天**：短期测试
     - **90 天**：推荐给常规使用
     - **180 天 / 365 天**：长期项目
     - **永久**：没有过期时间，但需要确认风险（不推荐）
4. 点击"创建"
5. **立即复制并保存完整 Key**（见下方重要提示）

**重要提示**：

完整 Key 只显示一次！关闭页面后无法找回。请立即复制并保存到：

- ✅ 后端服务的环境变量文件（`.env`，不要提交到 Git）
- ✅ 团队使用的密钥管理系统（如 HashiCorp Vault、AWS Secrets Manager）
- ✅ 受控的部署平台密钥配置

绝对不要：

- ❌ 保存到前端 JavaScript 代码
- ❌ 提交到 Git 仓库
- ❌ 放在 URL 查询参数中（如 `?api_key=xxx`）
- ❌ 写在聊天记录、邮件、工单或截图中
- ❌ 保存到浏览器书签或历史记录

**如果丢失 Key**：

无法找回。您需要：
1. 创建一个新的 Key
2. 更新程序中的 Key
3. 验证新 Key 可以正常调用
4. 禁用丢失的旧 Key

### 5.3 查看 Key 列表

在"API 密钥"页面，您可以看到所有已创建的 Key，包括：

| 显示项 | 说明 |
| --- | --- |
| 标签 | 您创建时填写的名称 |
| Key 前缀 | 例如 `agw_1a2b3c`，用于识别，不能用于调用 |
| 状态 | 可用 / 已过期 / 已禁用 |
| 过期时间 | 什么时候失效（永久 Key 显示"永久有效"） |
| 最后使用时间 | 最近一次成功调用的时间 |
| 创建时间 | Key 创建的时间 |
| 操作 | 复制前缀、禁用 Key |

**状态说明**：

- **可用**：正常使用中，可以调用接口
- **已过期**：超过有效期，不能继续使用
- **已禁用**：您或管理员手动停用，不能继续使用

**查看轮换提示**：

如果某个 Key 即将过期（14 天内），页面会显示黄色提醒，建议您提前创建新 Key 并轮换。

### 5.4 禁用 Key

**何时需要禁用 Key**：

- Key 泄露或怀疑泄露
- 测试完成，不再需要该 Key
- 发现异常调用
- 程序已停用，Key 不再使用
- 完成 Key 轮换，需要停用旧 Key

**操作步骤**：

1. 在"API 密钥"页面找到要禁用的 Key
2. 点击该行右侧的"禁用"按钮
3. 确认禁用

**禁用后**：

- 该 Key 立即失效，不能继续调用接口
- 使用该 Key 的调用会返回 401 错误
- 您无法恢复已禁用的 Key（但管理员可以，如果是误操作请联系管理员）
- 已禁用的 Key 仍然显示在列表中，方便追溯

**注意**：禁用 Key 前，确保您的程序已经切换到新 Key，否则会导致服务中断。

### 5.5 Key 轮换（更换 Key）

Key 轮换是定期更换 API Key 的安全操作，类似于定期修改密码。

**为什么要轮换 Key**：

- 降低 Key 长期泄露的风险
- 满足安全合规要求
- 及时发现和清理不再使用的 Key

**推荐轮换频率**：

- 生产环境：每 90 天
- 测试环境：每 180 天
- 临时测试：使用完立即禁用

**正确的轮换步骤**（重要！）：

**第 1 步：创建新 Key**

按照第 5.2 节的步骤创建一个新 Key，并立即保存完整 Key。

**第 2 步：更新程序配置**

将新 Key 更新到您的程序中：

- 如果使用环境变量：修改 `.env` 文件或部署配置
- 如果使用密钥管理系统：更新系统中的 Key
- 如果有多个服务：逐个更新（可以并行）

**第 3 步：验证新 Key 可用**

- 启动或重启使用新 Key 的程序
- 执行几次调用，确认返回正常
- 在"调用记录"中确认有新 Key 的成功调用记录

**第 4 步：禁用旧 Key**

确认新 Key 可用后，在"API 密钥"页面禁用旧 Key。

**错误的轮换方式**（会导致服务中断）：

- ❌ 先禁用旧 Key，再创建新 Key（会导致中间有一段时间无法调用）
- ❌ 创建新 Key 后忘记更新程序（旧 Key 过期后服务会中断）
- ❌ 更新程序后没有验证就禁用旧 Key（如果新 Key 有问题，无法回退）

**轮换检查清单**：

- [ ] 已创建新 Key 并保存完整值
- [ ] 已更新所有使用该 Key 的程序或服务
- [ ] 已验证新 Key 可以成功调用
- [ ] 已在"调用记录"中看到新 Key 的记录
- [ ] 已禁用旧 Key
- [ ] 已确认禁用旧 Key 后没有报错

### 5.6 Key 使用最佳实践

**创建 Key 时**：

- 为每个环境创建独立的 Key（生产、测试、开发）
- 为不同用途创建独立的 Key（数据处理、报表生成、监控）
- 使用清晰的标签，方便日后识别
- 优先选择有过期时间的 Key，而不是永久 Key

**使用 Key 时**：

- 只在后端服务中使用 Key
- 通过环境变量或密钥管理系统传递 Key，不要硬编码
- 在请求头的 `X-API-Key` 字段携带 Key，不要放在 URL 中
- 不要在日志中打印完整 Key（可以打印前缀用于排查）

**管理 Key 时**：

- 定期检查"API 密钥"页面的"最后使用时间"
- 长期未使用的 Key 应禁用
- 临期 Key 提前轮换，不要等到过期
- 发现异常调用立即禁用相关 Key

**Key 泄露应对**：

如果怀疑 Key 泄露（例如不小心提交到公开 Git 仓库）：

1. **立即禁用泄露的 Key**
2. 创建新 Key 并更新程序
3. 检查"调用记录"，查看是否有异常调用
4. 联系管理员说明情况，必要时审查泄露期间的调用
5. 复盘泄露原因，改进流程避免再次发生

### 6.4 理解访问范围

每个接口都有访问范围标识，说明谁可以调用：

| 访问范围 | 标识 | 说明 | 示例场景 |
| --- | --- | --- | --- |
| 平台用户可调用 | `authenticated` | 所有已审批用户都可以调用 | 公开查询、数据计算、格式转换 |
| 仅资源创建者 | `owner` | 只能访问自己创建的资源 | 查看我的任务、下载我的文件、删除我的数据集 |
| 平台用户共享 | `shared` | 所有用户看到相同的共享数据 | 全局配置查询、公共数据列表 |
| 仅管理员 | `admin_only` | 只有管理员可以调用 | 普通用户文档中不显示 |

**重要**：

- **`owner` 接口**：如果您尝试访问其他用户的资源（例如用别人的 `task_id` 查询任务），平台会返回 403 错误，拒绝访问。
- **`shared` 接口**：所有用户看到的数据都一样，没有隔离。管理员在发布时已经确认这些数据可以共享。
- **`authenticated` 接口**：不涉及个人资源的普通服务，所有用户都可以调用。

### 6.5 理解 Gateway 路径

**Gateway 路径的组成**：

```
[Gateway Base URL] + /gateway/ + [工具 slug] + [接口路径]
```

**示例**：

- **Gateway Base URL**：`https://api.example.com`
- **工具 slug**：`data-tool`
- **接口路径**：`/datasets/list`
- **完整 Gateway 路径**：`https://api.example.com/gateway/data-tool/datasets/list`

**注意**：

- 您在程序中使用的是 Gateway 路径，不是工具的真实服务器地址
- 工具的真实服务器地址不对普通用户公开，也不应在您的代码中使用
- Gateway 前缀（`/gateway/{工具slug}`）是固定的，不要修改

## 7. 调用 Gateway

### 7.1 调用的基本结构

一次完整的 API 调用包含四个部分：

**1. 请求方法（HTTP Method）**

| 方法 | 用途 | 示例场景 |
| --- | --- | --- |
| GET | 查询数据，不修改资源 | 获取数据集列表、查询任务状态 |
| POST | 创建新资源 | 创建数据集、提交分析任务 |
| PUT | 完整更新资源 | 更新数据集的所有字段 |
| PATCH | 部分更新资源 | 只更新数据集的名称 |
| DELETE | 删除资源 | 删除数据集、取消任务 |

**2. 请求 URL**

完整的 Gateway 路径，包括：
- Gateway Base URL
- `/gateway/` 前缀
- 工具 slug
- 接口路径
- 查询参数（如果有）

**3. 请求头（Headers）**

必需的请求头：
```
X-API-Key: agw_your_actual_key_here
```

某些接口还需要：
```
Content-Type: application/json
Idempotency-Key: unique_request_id_12345
```

**4. 请求体（Body）**

POST/PUT/PATCH 请求通常需要发送数据，格式通常是 JSON：
```json
{
  "name": "My Dataset",
  "description": "Test dataset",
  "tags": ["test"]
}
```

### 7.3 处理响应

**成功响应（状态码 2xx）**

成功时，接口返回 JSON 格式的数据，状态码通常是：
- **200 OK**：查询或更新成功
- **201 Created**：创建成功
- **204 No Content**：删除成功，无返回数据

示例：
```json
{
  "id": "dataset_123",
  "name": "My Dataset",
  "status": "ready",
  "created_at": "2024-01-15T10:30:00Z"
}
```

**错误响应（状态码 4xx / 5xx）**

失败时，接口返回标准错误格式：
```json
{
  "code": "INVALID_REQUEST",
  "message": "参数 name 不能为空",
  "request_id": "req_abc123xyz",
  "details": {
    "field": "name",
    "constraint": "required"
  }
}
```

**字段说明**：
- **code**：错误码，用于程序判断错误类型
- **message**：人类可读的错误描述
- **request_id**：请求编号，用于排障
- **details**：错误的详细信息（可选）

### 7.4 常见错误及处理

| 状态码 | 错误类型 | 常见原因 | 如何处理 |
| --- | --- | --- | --- |
| 400 | 请求错误 | 参数缺失、格式错误、数据验证失败 | 检查请求参数和数据格式 |
| 401 | 未授权 | 缺少 Key、Key 无效、已过期、已禁用 | 检查 `X-API-Key` 请求头，确认 Key 状态 |
| 403 | 权限不足 | 资源不属于您、账号被停用、工具未授权 | 检查资源 ID，确认账号状态 |
| 404 | 未找到 | 路径错误、接口未发布、资源不存在 | 检查 Gateway 路径和请求方法 |
| 413 | 请求过大 | 上传数据超过大小限制 | 减小请求体或分批上传 |
| 415 | 媒体类型错误 | Content-Type 不正确 | 使用 `application/json` |
| 429 | 超过限流 | 请求太频繁 | 降低请求频率，增加重试间隔 |
| 500 | 服务器错误 | 工具服务内部错误 | 保存 request_id，联系管理员 |
| 502 | 网关错误 | 工具服务不可达、资源校验失败 | 保存 request_id，联系管理员 |
| 503 | 服务不可用 | 工具已停用、正在维护 | 等待服务恢复，查看通知 |
| 504 | 网关超时 | 工具服务处理超时 | 不要立即重试写操作，联系管理员 |

**错误处理最佳实践**：

**1. 总是检查状态码**

```python
response = requests.post(url, headers=headers, json=data)

if response.status_code == 200:
    # 成功处理
    result = response.json()
elif response.status_code == 401:
    # Key 无效，检查配置
    print("API Key 无效或已过期")
elif response.status_code == 429:
    # 限流，等待后重试
    time.sleep(60)
    # 重试逻辑
else:
    # 其他错误
    error = response.json()
    print(f"错误 {response.status_code}: {error['message']}")
    print(f"Request ID: {error['request_id']}")
```

**2. 保存 request_id**

所有错误响应都包含 `request_id`，这是排查问题的关键信息：

```python
try:
    response = requests.post(url, headers=headers, json=data)
    response.raise_for_status()
except requests.exceptions.HTTPError as e:
    error_body = e.response.json()
    request_id = error_body.get('request_id')
    logger.error(f"API 调用失败，request_id: {request_id}, 错误: {error_body['message']}")
    # 可以将 request_id 发送到监控系统或日志
```

**3. 实现重试机制**

对于临时性错误（429、502、503、504），可以实现重试：

```python
import time
from requests.adapters import HTTPAdapter
from requests.packages.urllib3.util.retry import Retry

# 配置重试策略
retry_strategy = Retry(
    total=3,  # 最多重试 3 次
    status_forcelist=[429, 502, 503, 504],  # 这些状态码才重试
    backoff_factor=1  # 重试间隔：1s, 2s, 4s
)

adapter = HTTPAdapter(max_retries=retry_strategy)
session = requests.Session()
session.mount("https://", adapter)

response = session.post(url, headers=headers, json=data)
```

**注意**：
- 对于 **POST / PUT / DELETE** 等写操作，重试前要确认是否支持幂等
- 如果接口要求 `Idempotency-Key`，重试时必须使用相同的键
- 500 错误通常不应自动重试，应先排查原因

**4. 使用幂等键（Idempotency-Key）**

某些创建或更新接口支持幂等键，用于防止重复执行：

```python
import uuid

idempotency_key = str(uuid.uuid4())

response = requests.post(
    url,
    headers={
        "X-API-Key": "agw_your_key_here",
        "Content-Type": "application/json",
        "Idempotency-Key": idempotency_key
    },
    json=data
)

# 如果网络失败，使用相同的 idempotency_key 重试
# 平台会识别出这是同一个请求，不会重复创建资源
```

### 7.5 超时和重试策略

**设置合理的超时时间**

```python
# Python requests
response = requests.get(
    url,
    headers=headers,
    timeout=30  # 30 秒超时
)

# JavaScript fetch（需要手动实现）
const controller = new AbortController();
const timeout = setTimeout(() => controller.abort(), 30000);

fetch(url, {
  headers: headers,
  signal: controller.signal
})
  .then(response => response.json())
  .finally(() => clearTimeout(timeout));
```

**推荐超时设置**：
- **快速查询接口**：10-15 秒
- **普通接口**：30 秒
- **长时间任务接口**：60 秒或更长（根据接口文档）

**重试策略建议**：

| 错误类型 | 是否重试 | 重试次数 | 重试间隔 |
| --- | --- | --- | --- |
| 网络超时 | 是（查询接口） | 2-3 次 | 指数退避（1s, 2s, 4s） |
| 429 限流 | 是 | 3-5 次 | 60 秒固定间隔 |
| 502/503/504 | 是 | 2-3 次 | 指数退避 |
| 400/401/403/404 | 否 | - | 立即返回错误 |
| 500 | 否 | - | 保存 request_id 排查 |

**重试实现示例**：

```python
import time

def call_api_with_retry(url, headers, data=None, max_retries=3):
    for attempt in range(max_retries):
        try:
            if data:
                response = requests.post(url, headers=headers, json=data, timeout=30)
            else:
                response = requests.get(url, headers=headers, timeout=30)
            
            if response.status_code == 200:
                return response.json()
            elif response.status_code == 429:
                # 限流，等待后重试
                wait_time = 60
                print(f"限流，等待 {wait_time} 秒后重试...")
                time.sleep(wait_time)
            elif response.status_code in [502, 503, 504]:
                # 临时性错误，指数退避重试
                wait_time = 2 ** attempt
                print(f"临时性错误 {response.status_code}，等待 {wait_time} 秒后重试...")
                time.sleep(wait_time)
            else:
                # 其他错误不重试
                error = response.json()
                raise Exception(f"API 错误 {response.status_code}: {error['message']}, request_id: {error.get('request_id')}")
        except requests.exceptions.Timeout:
            if attempt < max_retries - 1:
                wait_time = 2 ** attempt
                print(f"请求超时，等待 {wait_time} 秒后重试...")
                time.sleep(wait_time)
            else:
                raise Exception("请求超时，已达最大重试次数")
    
    raise Exception("API 调用失败，已达最大重试次数")
```

### 7.6 并发调用注意事项

**限流额度**

您的账号和每个工具都有每分钟请求次数限制。并发调用时注意：

- 查看"使用概览"页面的限流信息
- 避免在短时间内发送大量请求
- 使用队列或线程池控制并发数
- 遇到 429 错误时降低并发

**并发控制示例**：

```python
from concurrent.futures import ThreadPoolExecutor, as_completed
import time

def call_single_api(item_id):
    response = requests.get(
        f"https://api.example.com/gateway/data-tool/items/{item_id}",
        headers={"X-API-Key": "agw_your_key_here"}
    )
    return response.json()

# 使用线程池，控制最大并发数为 5
item_ids = range(1, 101)
results = []

with ThreadPoolExecutor(max_workers=5) as executor:
    futures = {executor.submit(call_single_api, item_id): item_id for item_id in item_ids}
    
    for future in as_completed(futures):
        item_id = futures[future]
        try:
            result = future.result()
            results.append(result)
        except Exception as e:
            print(f"调用失败，item_id: {item_id}, 错误: {e}")
        
        # 可选：在每个请求之间增加短暂延迟
        time.sleep(0.1)
```

## 8. 资源与任务

### 8.1 什么是资源

资源是您通过调用接口创建或操作的数据对象，例如：

- **任务（Task）**：异步处理的工作项，例如数据分析任务、计算任务
- **数据集（Dataset）**：上传或生成的数据集合
- **文件（File）**：任务产生的输入、输出、日志文件
- **制品（Artifact）**：任务的最终结果文件，例如报告、图表
- **结果（Result）**：任务处理的结果数据

### 8.2 资源归属（Owner 模式）

**为什么需要资源归属**

平台可能有多个用户同时使用。为了保护您的数据安全，某些资源只能由创建者访问，其他用户无法看到或操作。

**资源归属的工作原理**

1. 当您调用创建接口（例如"创建数据集"）时，平台会记录这个资源属于您
2. 当您调用查询接口（例如"获取数据集详情"）时，平台会检查这个资源是否属于您
3. 如果资源不属于您，平台会返回 403 错误，拒绝访问

**如何识别 Owner 接口**

在接口文档中，访问范围标记为"仅资源创建者"或 `owner` 的接口，都属于 Owner 模式。

**典型的 Owner 接口**：
- 查看我的任务列表
- 获取任务详情
- 下载任务的输出文件
- 删除我的数据集
- 更新我的配置

**不要尝试访问他人的资源**

即使您知道了其他用户的资源 ID（例如 `task_456`），也无法通过修改 URL 访问：

```bash
# 这是您自己的任务，可以访问
curl "https://api.example.com/gateway/data-tool/tasks/task_123" \
  -H "X-API-Key: agw_your_key_here"
# 返回：200 OK，任务详情

# 这是其他用户的任务，不能访问
curl "https://api.example.com/gateway/data-tool/tasks/task_456" \
  -H "X-API-Key: agw_your_key_here"
# 返回：403 Forbidden，资源不属于您
```

### 9.4 理解常见错误

以下是最常见的错误及其排查方法。

#### 401 Unauthorized（未授权）

**可能原因**：

1. **缺少 X-API-Key 请求头**
   - 检查代码，确保包含 `headers: {"X-API-Key": "agw_..."}`

2. **API Key 无效**
   - 完整 Key 是否正确？是否包含 `agw_` 前缀？
   - 是否不小心使用了 Key 前缀而不是完整 Key？

3. **API Key 已过期**
   - 在"API 密钥"页面检查 Key 状态
   - 如果已过期，创建新 Key 替换

4. **API Key 已禁用**
   - 在"API 密钥"页面检查 Key 状态
   - 如果已禁用，确认是否是您自己或管理员操作
   - 创建新 Key 替换

5. **账号被停用**
   - 尝试登录平台查看账号状态
   - 联系管理员了解停用原因

**排查步骤**：

```bash
# 1. 检查 Key 格式
echo $API_KEY  # 应该以 agw_ 开头，长度约 50+ 字符

# 2. 测试 Key 是否有效（替换为实际地址和 Key）
curl "https://api.example.com/gateway/data-tool/health" \
  -H "X-API-Key: $API_KEY" \
  -v

# 3. 查看响应头，确认请求头是否正确发送
# 应该看到: X-API-Key: agw_xxx（部分内容）
```

#### 403 Forbidden（权限不足）

**可能原因**：

1. **访问他人的资源**
   - 您尝试访问不属于您的任务、文件或数据集
   - 检查资源 ID 是否正确（是否复制错了）

2. **工具未授权**
   - 您的 Key 不包含该工具的权限（罕见，新 Key 默认全局授权）
   - 联系管理员确认工具是否对您开放

3. **账号权限不足**
   - 接口标记为"仅管理员"，普通用户不能调用
   - 查看接口文档确认访问范围

**排查步骤**：

```python
# 确认资源 ID 是否属于您
# 1. 先调用列表接口，获取您的资源列表
response = requests.get(
    "https://api.example.com/gateway/data-tool/tasks",
    headers={"X-API-Key": "agw_your_key"}
)
my_tasks = response.json()
print([task['id'] for task in my_tasks])

# 2. 确认要访问的 task_id 是否在列表中
# 如果不在，说明不属于您或不存在
```

#### 404 Not Found（未找到）

**可能原因**：

1. **Gateway 路径错误**
   - 检查路径拼写，是否多了或少了字符
   - 确认是 `/gateway/{工具slug}/...` 格式

2. **请求方法错误**
   - 接口要求 POST，但您使用了 GET
   - 查看接口文档确认正确的方法

3. **接口未发布**
   - 管理员尚未发布该接口
   - 在"工具与接口"页面确认接口是否可见

4. **资源不存在**
   - 您访问的资源 ID 不存在或已被删除
   - 检查 ID 是否正确

**排查步骤**：

```bash
# 1. 从接口文档复制完整路径，不要手动拼接
# 错误示例：/gateway/datatool/query（缺少短横线）
# 正确示例：/gateway/data-tool/query

# 2. 检查请求方法
curl -X POST "https://api.example.com/gateway/data-tool/datasets" \
  -H "X-API-Key: $API_KEY" \
  -H "Content-Type: application/json" \
  -d '{"name": "Test"}'
# 如果文档说是 POST，不要用 GET

# 3. 检查资源是否存在
curl "https://api.example.com/gateway/data-tool/datasets/dataset_123" \
  -H "X-API-Key: $API_KEY"
# 如果返回 404，可能是 dataset_123 不存在
```

#### 429 Too Many Requests（超过限流）

**可能原因**：

1. **请求太频繁**
   - 在短时间内发送了过多请求
   - 查看接口文档的限流说明（例如每分钟 60 次）

2. **并发过高**
   - 多个程序或线程同时使用同一个 Key 调用
   - 降低并发数或增加请求间隔

**排查步骤**：

```python
# 1. 检查请求频率
import time

# 错误示例：循环内没有延迟
for i in range(100):
    response = requests.get(url, headers=headers)

# 正确示例：增加延迟
for i in range(100):
    response = requests.get(url, headers=headers)
    time.sleep(1)  # 每次请求间隔 1 秒

# 2. 收到 429 后等待 60 秒再重试
response = requests.get(url, headers=headers)
if response.status_code == 429:
    print("限流，等待 60 秒...")
    time.sleep(60)
    response = requests.get(url, headers=headers)
```

**联系管理员**：

如果您的业务确实需要更高的限流额度，可以联系管理员申请提高您的每分钟请求上限。

#### 500 / 502 / 503 / 504（服务器错误）

**可能原因**：

- **500 Internal Server Error**：工具服务内部错误
- **502 Bad Gateway**：工具服务不可达或资源校验失败
- **503 Service Unavailable**：工具已停用或正在维护
- **504 Gateway Timeout**：工具服务处理超时

**应对方法**：

1. **保存 request_id**：这是最重要的排障信息
2. **不要立即重试**：特别是写操作（POST / PUT / DELETE），可能导致重复执行
3. **查看通知**：进入"通知"页面，查看是否有维护公告
4. **联系管理员**：提供 request_id、调用时间、工具名称和接口路径

```python
# 服务器错误的正确处理方式
try:
    response = requests.post(url, headers=headers, json=data)
    response.raise_for_status()
except requests.exceptions.HTTPError as e:
    if e.response.status_code >= 500:
        error_body = e.response.json()
        request_id = error_body.get('request_id')
        print(f"服务器错误，request_id: {request_id}")
        print("请保存 request_id 并联系管理员")
        # 不要自动重试，等待管理员排查
        raise
```

### 9.5 联系管理员排障

**必需信息**：

1. **request_id**：在调用记录中复制完整的 request_id
2. **调用时间**：准确到分钟，包括时区
3. **工具名称或 slug**：例如"数据分析工具"或 `data-tool`
4. **接口路径**：例如 `/gateway/data-tool/datasets`
5. **请求方法**：GET / POST / PUT / DELETE
6. **状态码和错误码**：例如 502、`UPSTREAM_UNAVAILABLE`

**有帮助的信息**：

- 错误是否能稳定复现
- 是否在特定时间段发生
- 最近是否更新过程序或 Key
- 使用的 Key 前缀（不要发送完整 Key）
- 简化的请求参数（不要发送敏感数据）

**不要发送的信息**：

- ❌ 完整的 API Key
- ❌ 密码或其他凭证
- ❌ 敏感的业务数据
- ❌ 其他用户的资源 ID

**联系方式**：

- 管理员提供的工单系统
- 内部邮件或即时通讯工具
- 平台内的反馈入口（如果有）

- 或点击"全部标记为已读"按钮

### 10.2 处理 Key 临期通知

当收到 Key 临期通知时，建议立即处理，避免 Key 过期导致服务中断。

**处理步骤**：

1. 确认通知中的 Key 前缀和标签
2. 立即进入"API 密钥"页面
3. 创建一个新的 Key（参考第 5.2 节）
4. 按照第 5.5 节的轮换步骤更新程序
5. 验证新 Key 可用后，禁用即将过期的旧 Key

**不要等到过期当天**：

- Key 过期后立即失效，所有调用会返回 401 错误
- 提前轮换可以避免服务中断
- 推荐在收到 14 天或 7 天通知时就开始轮换

### 10.3 账户安全事件通知

如果收到以下通知，说明账户安全可能有问题：

**"您的账号已被停用"**

**可能原因**：
- 管理员发现异常调用
- 违反使用规定
- 账号长期不用被清理
- 其他安全原因

**应对措施**：
1. 查看通知中的停用原因
2. 联系管理员了解详情
3. 按管理员要求整改
4. 申请恢复账号

**"检测到异常调用"**

**可能原因**：
- Key 泄露，被他人使用
- 程序出现bug，发送大量异常请求
- 调用频率突然激增

**应对措施**：
1. 立即禁用所有 API Key
2. 检查"调用记录"，查看异常调用的时间和模式
3. 排查 Key 是否泄露（检查 Git 仓库、日志文件、聊天记录）
4. 创建新 Key 并更新程序
5. 联系管理员说明情况

### 10.4 账户安全最佳实践

**密码安全**：

- ✅ 使用至少 12 个字符的强密码
- ✅ 包含大小写字母、数字和符号
- ✅ 不在多个网站使用相同密码
- ✅ 定期更换密码（建议每 90 天）
- ✅ 使用密码管理器（如 1Password、Bitwarden）
- ❌ 不使用常见密码（如 `password123`、`admin888`）
- ❌ 不把密码写在纸上或未加密的文件中
- ❌ 不通过邮件或聊天发送密码

**API Key 安全**：

- ✅ 只在后端服务中使用 Key
- ✅ 通过环境变量或密钥管理系统传递 Key
- ✅ 定期轮换 Key（建议每 90 天）
- ✅ 为不同环境使用独立 Key（生产、测试、开发）
- ✅ Key 临期前提前轮换
- ✅ 长期未使用的 Key 及时禁用
- ❌ 不在前端 JavaScript 代码中使用 Key
- ❌ 不提交 Key 到 Git 仓库
- ❌ 不在 URL 查询参数中传递 Key
- ❌ 不在日志中打印完整 Key
- ❌ 不通过邮件、聊天、工单发送完整 Key

**调用监控**：

- ✅ 定期查看"调用记录"，确认是您的程序在使用
- ✅ 关注"API 密钥"页面的"最后使用时间"
- ✅ 如发现异常调用，立即禁用相关 Key
- ✅ 关注"通知"中的安全告警

**Key 泄露应对**：

如果怀疑 Key 泄露（例如不小心提交到公开 Git 仓库）：

1. **立即禁用泄露的 Key**（第 5.4 节）
2. 创建新 Key 并更新程序
3. 检查"调用记录"，查看泄露期间是否有异常调用
4. 联系管理员说明情况，必要时审查泄露期间的调用
5. 复盘泄露原因，改进流程避免再次发生
6. 如果 Key 提交到了公开 Git 仓库：
   - 禁用 Key 后，仍然要从 Git 历史中完全移除（rewrite history）
   - 仅删除当前文件不够，旧的 commit 中仍然保留 Key

## 11. 常见问题

### 11.1 账号相关

**Q: 注册后多久能通过审批？**

A: 通常在 1-2 个工作日内。管理员会核对您的申请信息和使用目的。如果超过 3 个工作日仍未审批，可以联系管理员查询。

**Q: 没有收到验证邮件怎么办？**

A: 
1. 检查垃圾邮件箱
2. 确认注册时填写的邮箱地址正确
3. 等待几分钟后重试
4. 如果平台未配置邮件服务，公开注册会关闭，请联系管理员开通账号

**Q: 忘记密码怎么办？**

A:
1. 如果平台配置了邮件服务：在登录页面点击"忘记密码"，按提示通过邮件重置
2. 如果平台未配置邮件服务：联系管理员为您重置密码

**Q: 账号被停用了怎么办？**

A: 联系管理员了解停用原因，按要求整改后申请恢复。

**Q: 可以修改用户名吗？**

A: 不可以。用户名创建后不能修改。如果确实需要新用户名，只能注册新账号。

### 11.2 API Key 相关

**Q: 创建 Key 时忘记保存完整 Key，怎么办？**

A: 无法找回。您需要创建一个新 Key，并禁用忘记保存的 Key。

**Q: 可以查看已创建 Key 的完整内容吗？**

A: 不可以。完整 Key 只在创建时显示一次，之后只能看到 Key 前缀。这是出于安全考虑。

**Q: 一个账号可以创建多少个 Key？**

A: 通常没有数量限制，但建议不要创建过多。为不同环境或用途创建独立 Key 即可（例如生产、测试、开发各一个）。

**Q: Key 可以延期吗？**

A: 不可以。Key 过期后只能创建新 Key 替换。建议在临期通知时就开始轮换。

**Q: 为什么建议定期轮换 Key？**

A: 
1. 降低 Key 长期泄露的风险
2. 符合安全合规要求
3. 及时清理不再使用的 Key
4. 类似定期修改密码的安全实践

**Q: 永久 Key 和有期限 Key 有什么区别？**

A: 永久 Key 没有过期时间，但风险更高。如果 Key 泄露但您不知道，可能长期被滥用。有期限 Key 即使泄露，影响范围也有限。推荐使用有期限 Key 并定期轮换。

### 11.3 调用相关

**Q: 为什么调用返回 401？**

A: 最常见原因是：
1. 缺少 `X-API-Key` 请求头
2. Key 填写错误（例如只用了前缀，或多了空格）
3. Key 已过期或已禁用
4. 账号被停用

详细排查请参考第 9.4 节。

**Q: 为什么调用返回 403？**

A: 最常见原因是：
1. 尝试访问不属于您的资源（例如其他用户的任务）
2. 工具未对您授权（罕见）
3. 接口仅限管理员调用

详细排查请参考第 9.4 节。

**Q: 为什么调用很慢？**

A: 可能原因：
1. 工具服务本身处理慢（例如复杂计算）
2. 网络延迟
3. 请求或响应数据量大
4. 工具服务负载高

建议：
- 查看"调用记录"中的耗时
- 如果持续很慢，联系管理员排查工具服务

**Q: 为什么调用返回 429？**

A: 请求太频繁，超过了限流额度。需要：
1. 降低请求频率
2. 增加请求间隔
3. 降低并发数
4. 如果业务确实需要更高额度，联系管理员申请

详细排查请参考第 9.4 节。

**Q: 调用失败后可以重试吗？**

A:
- **GET 请求**：可以安全重试
- **POST / PUT / DELETE**：谨慎重试，可能导致重复操作
  - 如果接口支持幂等键（`Idempotency-Key`），可以安全重试
  - 如果接口不支持幂等键，重试前先查询状态，确认操作是否已成功

详细说明请参考第 7.4 和 7.5 节。

**Q: 什么是 request_id？为什么很重要？**

A: request_id 是每次调用的唯一编号。当调用失败时，它是管理员定位问题的关键信息。管理员可以通过 request_id 查到同一次请求的完整日志，包括上游服务的错误信息。

### 11.4 资源和任务相关

**Q: 为什么我看不到任务中心？**

A: 任务中心只显示配置了任务能力的工具产生的任务。如果某个工具没有配置任务能力，您创建的异步作业不会在任务中心显示，但可以通过工具自己的接口查询。

**Q: 为什么我看不到某个任务？**

A: 可能原因：
1. 任务不属于您（只能看到自己创建的任务）
2. 任务 ID 错误
3. 工具没有配置任务能力

**Q: 任务失败了怎么办？**

A:
1. 进入任务详情查看错误信息
2. 根据错误信息调整参数
3. 重新提交任务
4. 如果错误信息不明确，保存 request_id 联系管理员

**Q: 文件下载失败怎么办？**

A:
1. 检查文件状态是否为"可下载"
2. 检查网络连接
3. 刷新页面重试
4. 如果仍然失败，联系管理员并提供文件 ID

**Q: 文件会保留多久？**

A: 通常是创建后 30 天（具体时间由管理员配置）。重要文件请及时下载保存。

**Q: 可以恢复已删除的文件吗？**

A: 通常不可以。删除操作是永久的。如果确实需要恢复，可以联系管理员尝试，但不保证能恢复。

### 11.5 其他问题

**Q: 平台支持哪些工具？**

A: 在"工具与接口"页面可以看到所有已开放的工具。工具列表由管理员维护，会随时间变化。

**Q: 可以申请接入新工具吗？**

A: 可以向管理员提出需求。管理员会评估工具的适用性和安全性，然后决定是否接入。

**Q: Gateway 地址会变吗？**

A: 通常不会。但如果平台迁移或升级，Gateway 地址可能改变。管理员会提前通知并提供新地址。

**Q: 可以直接访问工具的真实服务器吗？**

A: 不可以，也不应该。工具的真实服务器地址不对普通用户公开。所有调用必须通过 Gateway。

**Q: 平台会记录我的调用内容吗？**

A: 平台会记录调用的元数据（时间、工具、接口、状态码、耗时等），但不会完整记录请求体和响应体。记录已脱敏，用于排障和监控，不会泄露您的业务数据。

**Q: 调用记录会保留多久？**

A: 通常是 30-90 天（具体时间由管理员配置）。如需长期保留，请使用"导出 CSV"功能。

**Q: 遇到问题应该联系谁？**

A: 联系平台管理员。具体联系方式请咨询管理员或查看平台首页的联系信息。

| cancelled | 已取消 | 如需结果可重新提交 |

### 12.5 访问范围说明

| 访问范围 | 标识 | 说明 |
| --- | --- | --- |
| 平台用户可调用 | `authenticated` | 所有已审批用户都可以调用 |
| 仅资源创建者 | `owner` | 只能访问自己创建的资源 |
| 平台用户共享 | `shared` | 所有用户看到相同的共享数据 |
| 仅管理员 | `admin_only` | 只有管理员可以调用，普通用户不可见 |

### 12.6 联系管理员

**何时需要联系管理员**：

- 账号审批超过 3 个工作日
- 账号被停用，需要了解原因
- 调用返回 500/502/503/504 错误
- 怀疑 Key 泄露或发现异常调用
- 需要提高限流额度或存储配额
- 文件下载失败或文件状态异常
- 对接口文档有疑问
- 申请接入新工具

**联系时应提供的信息**：

- 您的用户名（不要发送密码）
- 问题的详细描述
- request_id（如果是调用相关问题）
- Key 前缀（不要发送完整 Key）
- 截图或错误信息

**联系方式**：

- 请咨询管理员获取具体联系方式（工单系统、邮件、即时通讯工具）
